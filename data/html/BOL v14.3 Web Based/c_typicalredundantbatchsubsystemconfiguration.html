Typical Redundant Batch subsystem configuration

Physically, the Application Stations are connected through the ACN (either as a simplex or redundant network) for normal ACN traffic. An additional, direct connection can be established between Application Stations in a redundant subsystem pair by using another network interface card in both Application Stations. This direct connection, or  Direct Link, provides an optimized pathway for the synchronization data to use.

Redundant Batch Subsystem Workstations in a Typical Configuration

Because the Direct Link connection is not physically redundant, the Batch Redundancy Server will redirect the synchronization data traffic to the ACN in the case of a Direct Link failure (or if Direct Link is not configured). The synchronization components in the Batch Redundancy Server are responsible for low-level communications (related to synchronization activities) between the workstations.

The Direct Link connection is reflected on the Advanced tab of the Node Properties dialog. The Direct Link's address is formatted the same as the ACN IP address format, resulting in a 10.12.x.x address on the primary (preferred active) workstation and a 10.13.x.x address on the secondary (preferred standby) workstation.

During the workstation configuration of the Application Stations in the redundant subsystem pair, the DeltaV system appends the characters _S, by default, to the name of the second Application Station of the pair. Therefore, the pair will be named <nodename> and <nodename_S>. When connecting to or configuring a default connection to the Batch Executive or Campaign Manager (for example, DeltaV Operate Batch Controls, Batch OI Configuration Tool, Campaign Manager Operator Interface, and so on), use the primary Application Station name <nodename>.

In Redundant Batch, the first computer in the pair that boots up becomes the active Batch Executive. Therefore, be sure to boot up the primary (preferred active) computer first if you want the designated preferred active to become the active node first. The second machine booted up becomes the standby Batch Executive.

Important:

There is a condition where both machines run as the Active Batch Executive. While rare, this can occur when communication between the preferred active and the rest of the DeltaV network is disrupted, and the pair is connected to the Plant LAN.

When communication between the preferred active and the rest of the DeltaV network is restored, the machine designated as the preferred active becomes the active node and the preferred standby computer (named with the _S) reboots (regardless of the option, Unattended reboot on switchover) and resumes in the standby role.

During the time of the 'dual' active Batch Executives, batches on the preferred standby may have started. Any new batch data on the preferred standby will not be updated on the preferred active when the preferred active resumes communications with the DeltaV network.

Always running the Batch Executive on the preferred active will negate any discrepancies in the Batch List caused by this dual active condition.
