Security properties for exported event history data sets

This topic is for system managers. It describes how to make sure the workstations and directories you specify for exported event history data sets have the correct security properties. Correct security settings are required in order for the DeltaV system to successfully export the data set files.

Security properties for automated data set exports

Automated exports include exports defined through the Advanced tab of the Alarms and Events Properties dialog in DeltaV Explorer and through the Event Chronicle Automated Backup Utility.

Fixed local drive properties - If the directory is on a fixed local drive, set directory security properties so that DeltaV Admins and DVECAdmin Windows groups have full control of the directory.

Shared drive properties - If the directory is a share on remote computer:

  • Make sure the Windows user DeltaVAdmin exists on the remote computer. The user account must have the same password on all computers and must be a member of the DeltaV Admins and DVECAdmin group.

  • Set directory security properties on the export directory so that DeltaV Admins and DVECAdmin Windows groups have full control of the directory.

In either case, test the security properties of the export directory by logging in as the DeltaVAdmin user and attempting to copy a test file to the directory. If you cannot successfully copy a test file to the directory, the system cannot export datasets to the directory.

Note:

This is the only time you should log in as the DeltaVAdmin. The DeltaVAdmin account is not a user account and should not be used as such.

Security properties for using the event chronicle administration tool

The export, backup and restore functions in the Event Chronicle Administration tool require specific security properties.

Fixed local drive properties - If the directory is on a fixed local drive, set directory security properties so that DeltaV Admins and DVECAdmin Windows groups have full control of the directory.

Shared drive properties - If the directory is a share on remote computer:

  • Make sure the Windows user DeltaVAdmin exists on the remote computer. The DeltaVAdmin user must have the same password on all computers and must be a member of the DeltaV Admins and DVECAdmin group.

  • Make sure that each Windows user that uses the Event Chronicle Administration tools exists on the remote computer with the same password.

  • Set directory security properties on the export directory so that DeltaV Admins and DVECAdmin Windows groups have full control of the directory.

In either case, test the security properties of the export directory by logging in as the DeltaVAdmin user and attempting to copy a test file to the directory. If you cannot successfully copy a test file to the directory, the system cannot export datasets to the directory.

Note:

This is the only time you should log in as the DeltaVAdmin. The DeltaVAdmin account is not a user account and should not be used as such.
