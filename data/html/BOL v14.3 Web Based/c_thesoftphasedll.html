The Soft Phase DLL

The Soft Phase DLL is responsible for handling all communications with the Soft Phase Server. The Soft Phase DLL implements the same phase state transitions that are used by controller-based phases. The Soft Phase DLL supports soft phases created with either Visual C++ or Visual Basic.

Note:

It may be necessary to recompile your soft phase with current versions of Visual C++ or Visual Basic compilers to work with updated versions of the Soft Phase DLL.

The Soft Phase DLL functions the same for Visual C++ or Visual Basic soft phases, except in one instance. For the Visual C++ soft phase, the DLL suspends the run logic immediately if a Hold, Stop or Abort command is received. The run logic is then resumed following a restart if the Restart Mode is set to continue. In some cases, the run logic may be in the middle of an operation that the user does not want interrupted when the command is received. To prevent this, the user can lock the run thread to prevent it being suspended during these types of operations.

For a Visual Basic (version 6 and prior) soft phase, there can only be a single active thread. This means the Soft Phase DLL cannot suspend the run thread and start the hold, stop or abort thread as it would for Visual C++ soft phase. The Soft Phase DLL cannot switch to the other logic until the run thread completes, therefore the user must write their run logic to periodically check the phase state. If the phase state is no longer running then the run logic should terminate allowing the hold, abort or stop logic to run. This is not true for Visual Basic .NET as that is multi-threaded.
