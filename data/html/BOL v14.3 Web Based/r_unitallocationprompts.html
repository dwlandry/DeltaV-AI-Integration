Unit allocation prompts

The following prompts are displayed to the operator when the system is either unable to automatically select the unit or the selection made will not validate. In either scenario, the operator must manually select the unit.  When referenced in the prompt, an unfiltered list contains all the units from the unit class for the unit alias as defined in the equipment train.

The flow chart scenarios in the topic, How Dynamic Unit Allocation Works, illustrate where potential problems can occur, necessitating an operator prompt.

Example Configuration Definition 

Aliases: AX -> AY -> AW

AX - units {UnitA, UnitF, UnitJ} - Step1
AY - units {UnitB, UnitC, UnitG} - Step 2
AW - units {UnitD, UnitE, UnitK} - Step 3

UnitA -> UnitB -> UnitD
UnitF -> UnitC -> UnitE
UnitG -> UnitK

Reselect Equipment Prompts and Unit Alias ToolTips

Prompt

Explanation

<UnitName> does not have required unit(s) downstream.

If the downstream unit alias is assigned, then <UnitName> does not have the assigned unit as its downstream unit.

If the downstream unit alias is not assigned, then the units that can be assigned to the downstream unit alias are not downstream of <UnitName>.

For example:

UnitA is assigned to unit alias AX on step 1.

UnitC is assigned to unit alias AY on step 2.

The reselect prompt that is issued during the execution of step1 is

UnitA does not have required unit(s) downstream.
The unit list provided contains { UnitF}

<UnitName> is not downstream of the upstream unit(s).

The unit is not listed as a downstream unit for the upstream unit alias, but there is at least one unit defined for this unit alias that is listed.

If the upstream unit alias is assigned then <UnitName> is not downstream of the assigned unit.

If the upstream unit alias is not assigned then <UnitName> is not downstream of any unit that can be assigned to the upstream unit alias.

For example:

UnitA is assigned to alias AX on step 1.

UnitC is assigned to alias AY on step 2.

Step 1 ran on UnitA.

The reselect prompt that is issued during the execution of step 2 is

UnitC is not downstream of upstream unit(s).
The unit list provided contains { UnitB}

This can be a configuration issue, especially where there is a convergence of two parallel steps. There must be at least one unit in common as a downstream unit for all upstream steps.

<UnitName> does not have required unit(s) downstream.  No units meet criteria, unfiltered list provided.

The unit is not found in the unit list of the downstream unit alias and no other units defined for this unit alias are found in the list.

If the downstream unit alias is assigned then <UnitName> does not have the assigned unit as its downstream unit.

If the downstream unit alias is not assigned then units that can be assigned to the downstream unit alias are not downstream of <UnitName>.

For example:

UnitA is assigned to alias AX on step 1.

UnitC is assigned to alias AY on step 2.

UnitK is assigned to alias AW on step 3.

Step 1 ran on UnitA.

The reselect prompt that is issued during execution of step 2 is

UnitC does not have required unit(s) downstream.
No units meet criteria, unfiltered list provided.
The unit list provided contains: 
{ UnitB, UnitC, UnitG}

<UnitName> is not downstream of the upstream unit(s). No units meet criteria, unfiltered list provided.

If the upstream alias is assigned then <UnitName> is not downstream of the assigned unit.

If the upstream alias is not assigned then <UnitName> is not downstream of any unit that can be assigned to the upstream alias.

For example:

UnitJ is assigned to alias AX on step 1.

UnitC is assigned to alias AY on step 2.

Step 1 ran on UnitJ.

The reselect prompt that is issued during execution of step 2 is

UnitC is not downstream of upstream unit(s).
No units meet criteria, unfiltered list provided.
The unit list provided contains: 
{ UnitB, UnitC, UnitG}

Unit list is not filtered:

(reasons A, B, D, & E possible)

(This prompt only applies to Tooltips for red unit aliases)

This tooltip appears on a red unit alias when it is not assigned ({Defer}). It indicates that there are no valid units to select from. No units passed the downstream equipment filtering. 

One reason for the error is listed in the prompt. Refer to the Downstream Equipment Filtering Failed Reasons table below for the reasons and explanations.
Downstream Equipment Filtering Failed Reasons - Unfiltered List of Units Displayed

Prompt

Explanation

A 

Unit bound to upstream unit alias <UnitAliasName> does not have downstream units.  

You are (or the system is) selecting a unit for a unit alias that is downstream of another unit alias.  At least one unit alias that is upstream of the one you are selecting is bound to a unit. That unit does not have any downstream units configured. Therefore, when the filtering is applied to determine the list of potential units for the one you are trying to select, that list is empty.

B 

Upstream unit aliases do not have common downstream units.

Where parallel paths converge, the unit aliases that are upstream of the convergence must have at least one common downstream unit to be selected for the step after the paths converge.

C 

Potential units are already assigned to other step(s) in the batch.

This only pertains to unit aliases with a selection mode of From_Policy.

All the units that passed the downstream equipment filtering have been assigned to other steps in this batch. You can select from the unfiltered list of units.

D 

Units defined for <UnitAliasName> are not downstream of the upstream unit(s).

The unit being assigned is not listed as a downstream unit for the upstream unit alias, and there are no other units defined for this alias that are listed.

If the upstream alias is assigned then <UnitName> is not downstream of the assigned unit.

If the upstream alias is not assigned then <UnitName> is not downstream of any unit that can be assigned to the upstream alias.

For example:

UnitJ is assigned to alias AX on step 1.

UnitC is assigned to alias AY on step 2.

Step 1 ran on UnitJ.

The reselect prompt that is issued during execution of step 2 is

UnitC is not downstream of upstream unit(s).
No units meet criteria, unfiltered list provided.
The unit list provided contains: 
{ UnitB, UnitC, UnitG}

E

Units filtered for <UnitAliasName> do not have applicable downstream units.

The unit is not found in the unit list of the downstream unit alias and no other units defined for this unit alias are found in the list.

If the downstream unit alias is assigned then <UnitName> does not have the assigned unit as its downstream unit.

If the downstream unit alias is not assigned then units that can be assigned to the downstream unit alias are not downstream of <UnitName>.

For example:

UnitA is assigned to alias AX on step 1.

UnitC is assigned to alias AY on step 2.

UnitK is assigned to alias AW on step 3.

Step 1 ran on UnitA.

The reselect prompt that is issued during execution of step 2 is

UnitC does not have required unit(s) downstream.
No units meet criteria, unfiltered list provided.
The unit list provided contains: 
{ UnitB, UnitC, UnitG}

F

All units are either unavailable or out of service.

This only pertains to unit aliases with a selection mode of From_Policy.

The possible valid units are either unavailable (as determined by the value of the $AVAILABLE parameter) or are OOS (as determined by the value of the MSTATE parameter).

G

No units meet the unit selection policy expression criteria.

This only pertains to unit aliases with a selection mode of From_Policy. 

The selection policy is evaluated to False on all filtered units. The list presented is filtered by downstream equipment filtering, equipment sorting and run-time filtering.

H

Unit selection policy expression evaluation timeout.

This only pertains to unit aliases with a selection mode of From_Policy.

The unit selection policy times out after 5 seconds. The list presented is filtered by downstream equipment filtering, equipment sorting and run-time filtering.
