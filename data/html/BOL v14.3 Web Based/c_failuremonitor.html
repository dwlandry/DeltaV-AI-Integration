Failure monitor

The Fail_Monitor composite is used to monitor process conditions to detect problems. The Fail_Monitor runs when the phase is active at the configured scan rate of the phase; however, it does not execute during either the phase's initial download nor final upload of parameter values.

You write code to set the FAIL_INDEX parameter to cause the phase to go into the HOLDING state. The Fail_Monitor is executed first within the phase; second, it executes whenever the phase status is not Idle, Completed, Stopped, or Aborted; and last, it is not executing when the current state logic is executing.

The Fail_Monitor, by default, contains an embedded Calc/Logic function block that monitors the process conditions. The expression that is included in the Calc/Logic block checks the state of the Watchdog parameter's current value and if it is Failed, sets the phase to Failed. The expression also checks the value of the Switched_Over parameter's current value and if True, sets the Fail_Index parameter to Controller Switchover Detected.

If the Watchdog parameter is not Failed or the Switched_Over parameter is False, then no failure is detected and the phase continues to run.

The following is the default Calc/Logic function block expression for the Fail_Monitor composite.

if ( '/+/WDOG_STATE.CV' = '$phase_wdog_states:FAILED' ) then
  '/+/FAIL_INDEX' := 'phase_failures:PLM Watchdog Failed';
endif;
if ( '/+/SWITCHED_OVER.CV' = TRUE ) then
  '/+/FAIL_INDEX' := 'phase_failures:Controller Switchover Detected';
  '/+/SWITCHED_OVER.CV' := FALSE;
endif;
Note:

You can change this expression by editing the embedded Calc/Logic function block in the Fail_Monitor composite.
