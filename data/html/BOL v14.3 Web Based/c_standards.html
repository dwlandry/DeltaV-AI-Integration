Standards overview

Standards provide a means to ensure a consistent graphics appearance within a DeltaV system by providing the standard values to be used system-wide. They are created and managed in configuration libraries and can be referenced by properties in displays, layouts, or GEM classes. Graphics Studios provides a multitude of out-of-the-box standards, including colors, fonts, Booleans, images, strings, measurements, and numbers. You can also create your own standards using the ribbon's New > Theme command or the Theme folder's right-click context menu. The name of a standard must be unique within its configuration library.

Configuring theme-specific values on a standard

Standards can also be configured with theme-specific values. A standard can have one theme-specific value (of the same type) for each theme existing in the database. When an active theme is applied in Graphics Studio or DeltaV Live, its theme-specific values replace the standards, system-wide, in all displays.

While theme-specific values are assigned to a theme, these values belong to their associated standard rather than the theme to which they are assigned. Figure 1 illustrates this concept.

Theme-specific values can be added to a standard using either the standard's Graphics Configuration pane or the Theme Guide. When you copy or delete a standard, all theme-specific values are copied or deleted with it.

Publishing standards

When standards are created, modified, or deleted, they must be published to deploy these changes online. When a theme-specific value is added to, deleted from, or modified for a standard, only the standard requires publishing; the affected themes do not. The displays, layouts, and GEMs that reference them do not need re-publishing.

For example, assume you have a theme, DB, and a standard, S_InfoTextColor. You modify the S_InfoTextColor's theme-specific values for the theme DB. Now you must publish S_InfoTextColor, but the DB theme does not require publishing.

Referencing standards

The properties that reference a standard are linked to that standard; therefore, when you modify the standard, all properties referencing the standard reflect the change. Likewise, when you delete a standard, all references to that standard are removed.

When importing configurations, references to standards that do not currently exist in the library can still be imported. You can later create a standard of the same type for that reference (Name must match), and the reference resolves without the need to publish. You can determine which references are missing a standard or do not match the expected type through graphics verification.
