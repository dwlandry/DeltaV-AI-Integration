Alias names

In order to create the base control logic in unit modules and their phases, alias names can be used the same as any other parameter reference path in actions, transitions, confirms, and so on. They can also be used in place of (or combined with) parameter reference path.

Alias names are supported in the following contexts:

  • The path string configured for external reference parameters

  • External reference parameters created at the unit module level (as defined by unit parameter definition in the unit class)

  • External reference parameters created at the unit phase level (as defined by algorithm parameters defined for the phase class)

  • The path string assigned to a dynamic reference parameter

  • Dynamic reference parameters created at the unit module level (as defined by unit parameter definition in the unit class)

  • Dynamic reference parameters created at the phase level (as defined by algorithm parameters defined for the phase class)

  • External parameter references in expressions used in phases (as defined by the phase algorithm definition part of the phase class)

  • Step expressions (right or left side of assignment operations)

  • Transition expressions

  • Boolean action expressions

  • Assignment action expressions (right or left side of assignment operations)

  • Action delay expressions

  • Action confirm expressions

  • Action confirm Timeout expressions

  • Expression in function blocks (Calc Logic, Action, Condition) in the Failure Monitor Composite

  • External parameter references used in Linked Composites

  • Note:

    While abstract linked composites can be shared in the configuration system and their definitions can be shared in the controller, they must be instantiated for each phase based on the currently applicable alias resolution table for that unit module.

  • Linked Composites used in Failure Monitor composite

  • Linked Composites used as xxxx_Logic SFC Composites (for example, to support the use of a common SFC composite used for both ABORT_LOGIC and STOP_LOGIC in the same phase, or the use of a common ABORT_LOGIC SFC composite for multiple phase classes).

Alias names are not supported in:

  • Internal reference paths

  • Internal reference parameters

  • Alarm parameters

  • Inside string constants (you must use string concatenation operators)

When used in a context where a parameter path string is supported, a leading and trailing pound sign (#) must identify alias names character, as follows:

  • When an alias name represents a module name. 

    'TEMP.CV' := '//#INLET#/PID1/PV.CV';

  • When an alias name represents a module and block name. 

    'TEMP.CV' := '//#INLET#/PV.CV';

  • When an alias name represents a module, block, and parameter of a parameter reference path. 

    'TEMP.CV' := '//#INLET#.CV';

  • When an alias name represents an entire parameter reference path. 

    'TEMP.CV' := '//#INLET#';

Effectively, the alias name (with the '#' characters) is replaced with the resolution string configured for that alias name. Therefore, there are no rules for what portion of a parameter reference path an alias name represents.

Note:

When using an alias' IGNORE field, the path does not include the # symbol. The correct syntax for the alias' IGNORE field is 

'/ALIAS.IGN'

(for example, 

'READ_IGN.CV' := '/ALIAS1.IGN'

).  This differs from the syntax used when referencing the IGNORE field of a class-based equipment or control module.

Recursively defined alias resolutions (that is, when the resolution string for an alias name itself has an alias name) are not supported.

You can embed an alias name into a string to display the specific alias resolution at run time. The following expression assumes you have defined an alias for #THISUNIT#, with the alias resolution table value containing that particular unit module's name (for example, REACTOR4). It also assumes you have another alias defined called XFER_VLV, with an alias resolution table value containing that particular unit module's transfer valve tag name (for example, XV101).

The following expression writes the string "Waiting for XV101 = CLOSED" to the user-defined String variable MSG1, which can then be used for display on an operator graphic.

'//#THISUNIT#/MSG1.CV' := "Waiting for " + '//#THISUNIT#/XFER_VLV.CV' + " = CLOSED";
