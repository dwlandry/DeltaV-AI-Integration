Archive sizing guidelines

This topic describes an approach to sizing the Advanced Continuous Historian archive files to meet the data recording needs of a specific implementation. Archives are the files that the Advanced Continuous Historian uses to store historical data. Each archive file contains events for a time period specified by the archive start time and end time. Since the Advanced Continuous Historian uses compression algorithms to reduce the amount of data storage, the information presented here will not provide exact results. However, information to estimate initial archive sizing and a methodology to view the actual data storage rate and adjust accordingly are provided.

The Advanced Continuous Historian system stores data into archive files. You can have multiple archive files of various sizes. The archive files range in size from 2 MB to 2 TB. The default installation configures one file of 256 MB. It is recommended that you create no fewer than three archive files. The maximum number of archives is limited by the operating system and the maximum file handles available, as well as by the available memory in the computer. The theoretical limit is tens of thousands of archive files, although the actual number is typically between 30 to 100 archive files on medium to large systems.

Consider the following when determining archive file size and count:

  • The total archive volume, the size of a single archive file times the number of archive files, affects the length of time that files store data before being overwritten.
  • The individual archive volume, the size of a single archive file, affects how often an archive shift occurs. The Advanced Continuous Historian performs an archive shift to switch archiving from the active file to the file that contains the oldest data.
  • The individual archive volume also affects how much available data is discarded when an archive shift occurs. For example, if each archive stored approximately one month of data and there were three archives, there would be a maximum of three months data online just prior to the shift and a maximum of two months data online after the archive shift.

Take the following items into consideration before setting the archive files:

  • Consider future expansion. Estimate the point count for the next year or two and size archive files accordingly.
  • Data storage rate increases with an increase in scan rate and decreases with an increase in compression deviation. The default compression values are Compression=ON with a Compression Deviation of 0. If this is left unchanged, every change in data values will be stored to disk, possibly consuming the archives much faster than expected.
  • Each point stored requires a minimum of 2 KB of storage for the archive system to work correctly. However, archive storage is more efficient if 5 KB per point are used.
  • An archive file can be any size, as long as it meets the minimum storage requirements, but it is recommended that all archives be the same size to facilitate system administration. Once created, the size of a fixed archive cannot be changed. It must be deleted and then recreated at the larger size. Therefore, it is much easier to add archives than to change archive sizes. Be generous in archive file sizing to meet the point count estimates and use the archive count to adjust for total archive duration.

General guidelines

Follow the general guidelines below to decide how to provision and size the archive files for the Advanced Continuous Historian. For specific questions or requirements, contact Emerson Technical Support.

  • Archive creation
    • Turn on Automatic Archive Creation. This feature is enabled by default for new installations of the Advanced Continuous Historian. The Advanced Continuous Historian will create new archive files as needed, which means that you will only need to monitor available disk space. For more information, refer to How PI 3.4 Automatic Archive Creation Feature Works (OSIsoft KB 3122OSI8).
    • Alternatively, you can create enough archive files to cover a given time range. Once all files are used and contain data, the Advanced Continuous Historian automatically overrides the archive file containing the oldest data. You can take this archive offline, turn its shift flag off, or mark it read-only if you don’t want data to be overwritten.
  • Archive type
    • Always use fixed-size archive files for the Primary storage area and all other archives receiving online data. The Advanced Continuous Historian automatically grows fixed-size archives if they become full. Such archives will be identified with the “auto-dynamic” type.
    • Dynamic archives can be used for older systems or for offline operations such as combining two or more small archives. For details about fixed size versus dynamic archives, refer to Advantages of using Fixed archives vs. Dynamic archives (OSIsoft KB 2998OSI8 ) and PI Server Reference Guide.
  • Recommended size
    • The default archive size is 256 MB. It is recommended that you use the default size.
    • Otherwise, archive file size should be kept between five and 10 times the expected point count, expressed in kilobytes (KB). For instance, a system with 30,000 points should function well with archive files between 150 MB and 300 MB.
    • The minimum archive size is 2,048 times the point count in bytes, which yields approximately 2 MB with 1,000 points.
  • Maximum size
    • The recommended maximum size of an archive is one-third of installed random access memory (RAM) on Windows Server. If point count and archive sizing needs exceed recommended maximum size, you should consider installing more memory.

Additional considerations

Consider the items below when deciding on archive size:

  • Data rates

    Archive size should provide a balance between data rates, storage consumed per unit of time, and shift frequency, number of files per unit of time. Increasing shift frequency is usually better than increasing archive size beyond the recommended range.

    You can find data rate information for your archives by using the Archives plugin in the PI System Management Tools (PI SMT), or by running the piartool -al command. Each registered archive shows the Add Rate/Hour which is the average rate of records in kilobytes used per hour to the archive, showing how quickly the archive files are filling up.

  • Compression settings

    Although disk space is usually inexpensive, disk access – in bytes and/or I/O per second – remains expensive. Be sure to apply the appropriate compression settings for tags on large systems as this will reduce disk space used and increase disk access performance. For more information about recommended exception and compression settings, refer to What are recommended Exception and Compression settings (OSIsoft KB 3226OSI8).

  • Windows file system cache

    Archive throughput will improve when the archive size is significantly smaller than the Windows File System Cache (FSC) so that the most commonly requested data resides in memory. For more information, refer to File Cache Performance and Tuning at the Microsoft TechNet web site. No limit for maximum FSC size exists for Windows Server operating systems.

    You can monitor cache and disk performance by looking at the Windows Performance Counters: Cache\Copy Read Hits % and Physical Disk(<Volume>)\% Idle Time. Values significantly above 90% for both of these counters usually indicate a healthy system.

  • System backups

    Since the most recent archive files are usually backed up in every system backup, do not create archives that exceed the limits of your physical backup media. Smaller files will also speed up the verification phase of the Advanced Continuous Historical backups.

For specific details about the Advanced Continuous Historian archive sizing and storage space utilization, refer to the Hardware System Sizing Recommendations spreadsheet accompanying the Advanced Continuous Historian documentation.
