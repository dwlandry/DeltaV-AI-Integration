Two-way valve module templates

There are two categories of module templates for two-way valve control, one for normally closed valves (fail closed) and one for normally open (fail open) valves. In each category there are variations for valves with one or two limit switches and valves with or without interlock conditions. The valve module templates are similar to the motor module templates. If you are not familiar with the motor module templates in the Library, read Two-state motor module templates before proceeding.

A normally closed valve is closed in the passive state. An interlock condition causes the valve to close. A normally opened valve is open in the passive state, and an interlock condition causes it to open. The two-way valve modules have one or two discrete inputs, depending on the number of limit switches. There is a single latching discrete output to drive the valve open or closed. The STATE_MASKS parameter of the Device Control block is a Quick Config parameter in the valve module templates, which enables the inputs and output to be inverted when necessary. For valves with interlocks, you can optionally configure the valve to automatically return to the active state when the interlock conditions clear. For example, a normally closed valve would be driven closed on an interlock, but could be configured to open when the interlock clears if the previously commanded state was Open. This is done by disabling the SP Track option in DEVICE_OPTS of the Device Control block.

Quick Config parameters for the Two-Way Valve module templates

Parameter

Description

IO_IN_1

An I/O Reference parameter that configures the DST for the Open/Close status (1=CLOSED, normally closed valve with one limit switch), Open/Close status (1=OPEN, normally open valve with one limit switch), Close status (1=CLOSED, normally closed valve with two limit switches).

IO_IN_2

An I/O Reference parameter that configures the DST for the Open status of the valve (1=OPEN) (two limit switches) (not a Quick Config parameter for valve modules with one limit switch)

IO_OUT_1

An I/O Reference parameter that configures the DST for the latching output to the valve (1=OPEN for normally closed valves, 1=CLOSE for normally open valves).

CFM_ACT1_TIME

The amount of time in seconds for the valve to confirm that it is in the active state (Open for a normally closed valve, Closed for a normally open valve) following a command to that state. If the valve does not confirm within this time, a fail condition occurs. The default is 15 seconds.

CFM_PASS_TIME

The amount of time in seconds for the valve to confirm that it is in the passive state (Closed for a normally closed valve, Open for a normally open valve) following a command to that state. If the valve does not confirm within this time, a fail condition occurs. The default is 15 seconds.

CRACK_TIME

The amount of time in seconds for the valve to begin movement to a new state following a command to the new state. The crack time should be less than the confirm times so that a fail condition can occur more quickly when a valve with a long travel time has not cleared the old confirm. The default is 5 seconds.

DEVICE_OPTS

Configuration options for the Device Control block. The option that defaults to enabled for modules without interlock conditions is SP Track. The options that default to enabled for modules with interlock conditions are SP Track, Permissive, and Interlock.

Note: When you want the valve to return to the previously commanded active state when an interlock condition clears, clear the SP Track check box. Reset required is a device option that is not enabled as a default, but is applicable to two-way valves.

STATE_MASKS

A Quick Config parameter that enables the output to the valve (or feedback from the valve) to be inverted when necessary.
