Understanding active step changes

Operators can perform active step changes to alter the sequence of the steps in a batch. Typically, an active step change is performed to return a batch to a specific step due to a problem in the execution of that particular step. For example, the problem could be an equipment malfunction, or to add a missing ingredient in the batch. In either case, once the problem is corrected, the operator can then rerun the batch at the point of the problematic step by using active step change.

The logged in user must have the Batch_Active_Step_Change key to execute an Active Step Change.

Important:
  To perform an active step change the following must be true:

  • The step you are performing the active step change from must be in a terminal state; that is, Complete, Stopped, Aborted, Stopped_NC, or Aborted_NC.

  • The parent steps of the one you are changing from must be in one of the following states:  Held, Running or Ready

  • The active step change cannot be performed if the batch or the parent step is in a terminal state (Complete, Stopped, Aborted).  However, the operator can reset the batch into an active state if the batch is in a terminal state.

If the active step change fails, the state is listed as ASC_Failed. The operator can enter the ASC mode again and either cancel or retry the active step change.
