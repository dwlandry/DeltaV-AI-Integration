Using the request and reqdata parameters

The phase logic uses requests to ask the Batch Executive to perform various tasks, such as phase-to-phase messaging, operator messaging, and releasing and acquiring resources.

Additionally, you can use the REQUEST parameter to synchronize phases.

Phase requests are programmed in the phase logic by using an action that writes a value to the phase's REQUEST parameter. The REQUEST parameter is the mechanism that interacts with the DeltaV Batch Executive from the phase logic. By setting the REQUEST parameter to specific values, the phase can cause the Batch Executive to acknowledge that the phase needs attention and then to service the request. Once the request is serviced, the Batch Executive writes back to the REQUEST parameter, setting the value back to zero (0).

Note:

It is very important that your phase waits for the Phase Request to be completed, as signified by the REQUEST register returning to 0, before issuing another request. If you fail to do this, the requests may fail. Always follow any step that writes a value to REQUEST with a transition expression that waits for 'REQUEST' = 0. For some types of request, such as the "Acquire Resource" request, this could result in a lengthy wait.

CAUTION:

It is not recommended to send requests in the Hold logic. However, if a request must be used, always check the to see if the Watchdog has tripped first. Write the logic to not sent the request if the Watchdog is tripped. Failing to do this can cause the phase to be unable to resume.

Phase request codes are the values written to the REQUEST parameter. Each phase request code is a different action or message that the Batch Executive reads and handles. The REQDATA1...5 parameters are used for requests that allow the use of an allocated location, REQDATA1...5, to contain the request argument, that is, the number or ID.

Note:

Only one request can be issued at a time. This is especially important when configuring parallel divergent paths in your SFC.
