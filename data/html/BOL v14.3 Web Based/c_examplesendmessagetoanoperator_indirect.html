Example send message to an operator, indirect

In the preceding example, there is only one message, and it is always the message sent to the operator when the AGITATE phase starts. You can configure messages to the operator that vary depending on conditions in the plant. This is called indirect messaging.

For example, you can send a message informing the operator how fast the motor in the agitation tank is going. Here you will configure four (4) messages: Slow, Medium, Fast, and Very Fast. Create the messages in DeltaV Explorer.

Example Indirect Phase Message IDs

ID

Request Type

2

Motor speed is SLOW

3

Motor speed is MEDIUM

4

Motor speed is FAST

5

Motor speed is VERY FAST

In the AGITATE phase's logic, select the Running state. Write a condition equation (MSG_SPEED) to determine the speed of the motor as either 2, 3, 4 or 5 (corresponding to the above table of messages).

Write the action for the step to call a phase message ID depending on the result of MSG_SPEED. The action should have a Type of Assignment and a Qualifier of Pulse. The phase register is 3000, (Send Message to the Operator, Indirect) and the REQDATA1 is equal to the MSG_SPEED value (2 through 5).

Indirect Phase Message Step Action

In the transition immediately following this step, write an expression that waits for the message to clear before moving to the next step.

Note:

It is very important that your phase waits for the Phase Request to be completed, as signified by the REQUEST register returning to 0, before issuing another request. If you fail to do this, the requests can fail. Always follow any step that writes a value to REQUEST with a transition expression that waits for 'REQUEST' = 0. For some types of request, such as the Acquire Resource request, this could result in a lengthy wait.

Phase Message Transition Expression

If you need to abort an outstanding request before it has completed (that is, before REQUEST has returned to 0), you can set REQUEST to 6000. This is the only case where it is valid to change REQUEST without waiting for it to reset to 0.

Note:

It is better to avoid parallel paths in the SFC that are each issuing requests because of the risk of two requests colliding.
