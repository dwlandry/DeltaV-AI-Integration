Working with deferred recipe parameters

At any recipe level, you can define recipe parameters where the value of those recipe parameters are set at the next recipe level or by formulas. You can also set the values (or origin of values) for step parameters with a recipe parameter. You defer a step parameter to a recipe parameter when you want to allow a higher level recipe or a formula selection to determine the value of the step parameter.

All recipe parameters become step parameters when that recipe is used in the next higher recipe level. For example, there a recipe parameter in an operation becomes a step parameter in a unit procedure (for the step that references the operation). Also, all phase parameters in the operation become step parameters in the unit procedure. Consider the operation in the following figure. Notice that there are values for the phase parameters, AMOUNT_TO_CHARGE and MIX_TIME. The operation always uses these values, unless the parameters are deferred to recipe parameters in the operation and their value is set at the next recipe level (a unit procedure in this case).

Sample Operation with Deferred Step Parameters

To make the operation generic, you can add a recipe parameter that allows you to pass in any value you want. The operation shown in the preceding figure contains two recipe parameters; BASE_CHARGE_AMOUNT and BASE_MIX_TIME. The phase parameters, AMOUNT_TO_CHARGE and MIX_TIME are deferred to the operation's recipe parameters. By deferring the parameters, you instruct the operation to disregard the default values of those parameters and receive the values from the recipe parameter.

You can continue to defer the values for these parameter to the next higher level recipe (a unit procedure in this case). The unit procedure will reference the operation MAKE_BASE in a step which makes the operation's recipe parameters (BASE_CHARGE_AMOUNT and BASE_MIX_TIME) into step parameters of that unit procedure. To continue this, you can defer the unit procedure's step parameters into recipe parameters. In our example, the step parameters (CHARGE:BASE_CHARGE_AMOUNT and MIX:BASE_MIX_TIME) are deferred to the unit procedure's recipe parameters, CHARGE_AMT and MIXTIME (respectively). The unit procedure then sets the values of these parameters and those values are passed down to the phase parameters through the step parameters of the operation during production.

Deferring Values up to a Unit Procedure

Of course, you do not have to set the values of the step parameters at the unit procedure level. You can defer the value of these step parameters by deferring the unit procedure level recipe parameters up to the procedure level. This is the same process as deferring the operation's recipe parameters to the unit procedure level.

When the unit procedure is used by a procedure, the unit procedure's recipe parameters become the procedure's step parameters (UP:CHARGE_AMT and UP:MIXTIME). The procedure is the highest recipe level. You can defer the procedure's step parameters to recipe parameters (C_AMT and M_TIME). Deferring a procedure's step parameter to a procedure-level recipe parameter allows you to have a generic procedure. In the procedure, you can write different formulas and select the appropriate one at run-time or defer the value to the operator (by setting the Origin field to Operator).

When you defer a parameter to the operator, you are allowing an operator to enter a value through an operator graphic. However, the parameter that the operator is setting must be linked all the way down to a phase parameter. The operator is prompted through the Batch Operator Interface to enter a value when the procedure runs and that step is active.
