Components of a VBA project

Visual Basic for Applications, or VBA, is the standard scripting language built into DeltaV Operate. VBA was once only available in Microsoft Office applications. However, Microsoft has made VBA available through licensing, so companies can integrate the language directly into their products.

VBA can be used to customize and extend the functionality of DeltaV Operate. For example, you can create a custom wizard that automatically builds a picture at the click of a button. In addition, VBA enables you to manipulate, retrieve, and modify data from applications. For example, you can manipulate the objects in a DeltaV Operate picture based on the information in a Microsoft Word document. When you use VBA with DeltaV Operate, you build the most powerful industrial automation solution available.

Once you begin working with the DeltaV Operate object model, you will start to understand how powerful VBA really is. Through VBA, you can:

  • Extend or customize the functionality of DeltaV Operate.

  • Create your own custom dialog boxes to exchange data with operators.

  • Create wizards that can perform several tasks at the click of a button.

Let's take a look at the components of a VBA Project.

Host Application

All VBA projects must be associated with an application; you cannot create a stand-alone VBA project. The application that the VBA project is tied to is called the host application. In the case of DeltaV Operate, the host application is DeltaV Operate, and each VBA project is embedded in a picture file (*.GRF), toolbar file (*.TBX), toolbar category file (*.TBC), schedule file (*.EVS), Dynamo set file (*.FDS), or User file (USER.FXG).

Visual Basic Editor

The Visual Basic Editor, or VBE, is the development environment that allows you to write and debug code, develop user forms, and view the properties of your VBA project.

Modules

If you are developing large VBA projects, it may make sense to separate the code into several modules. Modules are self-contained blocks of code that perform a particular function. For example, if you wanted to write a wizard that creates a real-time chart for a specific data point, you may want to break the project up into three modules: one module to retrieve the value after prompting the operator to specify a data source, one module to plot the data after prompting the operator to specify a chart type, and one module to create the chart based on the operator's specifications.

Note:

Do not include modules in Dynamos, since they are not moved with the Dynamo object.

Forms

Forms are custom dialog boxes that you create in VBA in order to exchange information with the operator. Examples of forms are message boxes, input dialogs, and configuration screens. Forms are essential in helping the application and the operator interact.
