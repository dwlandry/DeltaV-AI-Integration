Configuring user accounts for OPC server and clients

OPC uses Microsoft DCOM technology to allow a client to connect to a server running across a network that uses TCP/IP. Any two machines configured for DCOM communications can be set up to run as a DeltaV OPC client and server.

Note:

When configuring the OPC Mirror user (opcuser in our examples), you must, in DeltaV User Manager, grant the proper DeltaV groups and DeltaV keys to opcuser. This means if you are using OPC Mirror to write parameters to the DeltaV runtime system and those parameters are in modules running assigned to a specific area, you must grant the OPC Mirror user the Control key for the DeltaV area where those parameters are assigned. Or, you can add that OPC Mirror user to a DeltaV group that has the Control key for the DeltaV area where those parameters are assigned.

Client machine setup

For unsolicited callbacks to work, set the password for the DeltaVAdmin account on the client machine to be the same as that on the server machine. This is because the OPC server is running as DeltaVAdmin on the server machine. The DeltaVAdmin account is automatically created by the OPC Remote installation.

Server machine setup

The client application runs as a valid Windows account and DeltaV account to the server machine. The server is set up differently depending upon whether the computers are in a workgroup or domain. The following sections describe the various setup options. The term "opcuser" is used as an example user account name.

Both client and server machines are in a workgroup

The client runs as a local user if both client and server are in a workgroup. To set up the user on the server machine:

  • Use the DeltaV User Manager on the server machine to create a user account (opcuser, for example) and assign it the same password as the client machine.

  • In DeltaV User Manager, make opcuser both an Operating System Account and a DeltaV Database Account.

  • In DeltaV User Manager, grant the proper DeltaV groups and DeltaV keys to opcuser.

  • From DeltaV Explorer, download the DeltaV machine.

The client runs as a domain user and the server is in a workgroup

Follow the steps described in the section: Both the client and server machines are in a workgroup.

Also, create the DeltaVAdmin account on the server (the DeltaV workstation) as follows:
  • as a local user account, with the same password as the domain account and also the client's local account.
  • Make the local DeltaVAdmin account a member of the local DeltaV user group.
  • Make the local DeltaVAdmin account a non-interactive account (the same as the domain DeltaVAdmin account).

The client runs as local user and the server is in a domain

On the server machine, use the Windows User Manager application to:

  • Create a local user account (opcuser, for example).

  • Assign it the same password as the client machine.

  • Add it to the local DeltaV group.

On the server machine, use DeltaV User Manager to:

  • Make the local account (in this example, opcuser) a DeltaV Database account (select that option in the user account's properties).

  • Grant the proper DeltaV groups and DeltaV keys to opcuser.

On the server machine, use DeltaV Explorer to download the DeltaV machine.

The client runs as domainA user and the server is in domainB and domainB trusts domainA

When establishing the trust, configure the domain name system (DNS) for the domain being trusted using the DNS Manager on domainB's domain controller.

On the server machine (domainB), do the following:

  • Use Windows User Manager to add domainA\opcuser to the local DeltaV group.

  • Use the DeltaV User Manager to make opcuser a DeltaV Database account (select that option in the user account's properties).

  • In DeltaV User Manager, grant the proper DeltaV groups and DeltaV keys to this user.

  • From DeltaV Explorer, download the DeltaV machine.

The client runs as domainA user and the server is in domainB and there is a two-way trust between the domains

When establishing the trust, configure the domain name system (DNS) for the domain being trusted using the DNS Manager on the domain controller (in this case, both domains will have a DNS entry for each other).

On the server machine (domainB), do the following:

  • Use Windows User Manager to add domainA\opcuser to the local DeltaV group.

  • Use the DeltaV User Manager to make opcuser a DeltaV Database account (select that option in the user account's properties).

  • In DeltaV User Manager, grant the proper DeltaV groups and DeltaV keys to this user.

  • From DeltaV Explorer, download the DeltaV machine.

In this scenario, the domainA (client side) does not need the local DeltaAdmin account that is created by OPC Remote installation.

The client runs as domainA User and the server is in domainB, and domainB does not trust domainA

Follow the steps described in the section: The client runs as local user and the server is in a domain.
