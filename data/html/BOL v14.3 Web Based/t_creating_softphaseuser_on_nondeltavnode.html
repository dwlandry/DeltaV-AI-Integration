Creating the SOFTPHASEUSER on the Non-DeltaV Node

  1. On the DeltaV system, run Windows User Manager to set the privileges (if necessary) for the SOFTPHASEUSER.
    When DeltaV is in a domain, and the non-DeltaV node is in a workgroup, you must
    1. Create a local SOFTPHASEUSER account on the DeltaV node that you are connecting to.
    2. Make the password match the domain SOFTPHASEUSER account.
    3. Set any Windows privileges if needed for the local SOFTPHASEUSER. These should be the same as the domain SOFTPHASEUSER account has, but only on the local computer.
    4. Set the local SOFTPHASEUSER as a non-interactive user. That is, the user account cannot be used to log onto Windows. This can be set using GPOs or local policies (in a workgroup).
  2. When DeltaV is in a domain, and the non-DeltaV node is in a workgroup, you must create a local DeltaVAdmin account on the DeltaV node that you are connecting to.
    1. Log on to Windows as an administrator on this computer.
    2. Using Windows User Manager, create a local account named DeltaVAdmin.
    3. Assign it the same password as the domain DeltaVAdmin account.
    4. Make it a member of the local DeltaV group.
    5. Set this account as a non-interactive user. That is, the user account cannot be used to log onto Windows. This can be set using GPOs or local policies.
  3. On the DeltaV node, log on to Windows as an administrator and run DeltaV Security Administration. In a domain, log on to Windows as a domain administrator. In a workgroup, log on to Windows as a local administrator.
  4. Set the SOFTPHASEUSER account password.
    Note:

    This password must match between the DeltaV node (both local and domain accounts) and the non-DeltaV node.

  5. On the non-DeltaV machine, create the SOFTPHASEUSER account using Windows User Manager.
    1. Assign it any privileges needed.
    2. Set the account as a non-interactive user. That is, the user account cannot be used to log onto Windows. This can be set using GPOs or local policies.
    3. Set the password to be the same password that you created for this account on the DeltaV node.
  6. On the non-DeltaV node, create a local DeltaVAdmin account using Windows User Manager.
    1. Assign it any privileges needed.
    2. Set the account as a non-interactive user. That is, the user account cannot be used to log onto Windows. This can be set using GPOs or local policies.
    3. Set the password to be the same password that you created for this account on the DeltaV node.
    4. Add the DeltaVAdmin account to the local administrators' group. Alternately, you can add the DeltaVAdmin account in DCOM Launch and Activate.
