Procedural function chart execution flow

The basic execution flow of a recipe is as follows:

  1. The initial step of the recipe runs and arms its transition.

  2. Once armed, the DeltaV system monitors the value of the transition.

  3. When the transition evaluates to true, the DeltaV Batch system deactivates the preceding steps and activates the subsequent steps and transitions.

  4. Once the subsequent steps are connected, the transitions following them are armed.

  5. The connected steps are issued Start commands.

These steps (2 through 5) are repeated until the entire recipe has been executed.

This basic flow is repeated at every level of the procedural hierarchy with the following additions:

  • If the current step is another recipe, when it starts to run, the execution passes down one level of the procedural hierarchy, and the recipe at that level starts to run. For example, when the step ADDITIVE runs, the execution passes down to the unit procedure ADDITIVE and the first step of the unit procedure starts to run.

  • When there are no more steps in a recipe at a specific level, the execution passes up one level in the procedural hierarchy. When this happens, the transition of the active step at the higher level is evaluated. If the transition evaluates to true, the recipe continues to the next step.

  • If two steps follow the currently armed transition, both steps execute simultaneously when the transition evaluates to true. Thereafter, each branch executes as previously described.

  • A phase's STEP_INDEX is reset to zero (0) after the phase is sent a Start command.

Passing Control Between Procedural Function Charts

Consider what happens when the following application runs:

  1. A command is sent from the Batch Operator Interface to the DeltaV Batch Executive to start the MAKE_PAINT recipe.

  2. The initial step of the procedure runs and arms its transition.

  3. Once armed, the DeltaV system monitors the value of the transition. Since this transition is TRUE, the initial step stops running and the BASE and ADDITIVE steps in the And sequence selection start running simultaneously.

  4. The DeltaV system then examines each step to determine if either step is a recipe.

  5. Since both steps are recipes, the DeltaV system passes execution down to the unit procedures BASE and ADDITIVE. As a result, the initial steps of these recipes start running and their transitions arm.

  6. Once armed, the DeltaV system monitors the values of these transitions. Since both transitions are TRUE, the initial steps stop running and the MAKE_BASE and MAKE_ADDITIVE steps start running.

  7. The DeltaV system then examines each step to determine if either step is a recipe.

  8. Since both steps are recipes, the DeltaV system passes execution down to the operations MAKE_BASE and MAKE_ADDITIVE. As a result, the first steps of these recipes start running and their transitions arm.

  9. Each phase in these operations executes. When the two operations complete, execution passes back to the BASE and ADDITIVE unit procedures and then back to the top level procedure MAKE_PAINT.

  10. When both unit procedures are complete, the transition following these steps evaluates to TRUE and the MAKE_FNL step starts to run.

  11. The recipe continues as described until the last phase completes and passes control back to the top-level procedure. Then the recipe ends.
