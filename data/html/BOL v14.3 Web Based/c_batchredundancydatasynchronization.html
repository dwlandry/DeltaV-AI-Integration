Batch redundancy data synchronization

The batch system supports a warm restart capability that allows batches and campaigns to recover (upon being restarted) to the state they were in prior to shutting down. This restart mechanism functions by consistently saving pertinent data (the state of a batch/campaign or value of a parameter, for example) which can be accessed upon restart, allowing the system to attempt to progress back to the state it was in prior to shut down. With batch redundancy, this data is transferred from the active to the standby, allowing the standby to recover with the persisted data. Transferring the persisted data occurs by two mechanisms: initial updates, and runtime synchronization.

Initial updates are triggered on the active when the standby node's state changes to INITIALIZING. The INITIALIZING state is forced upon the standby by the DeltaV redundancy subsystem once the standby node registers with the redundancy subsystem. The standby node will be configured upon download of the active node. This means that initial updates can be delayed by total and partial downloads occurring when the standby is booting up. Downloads do not, however, have an effect on initial updates already in progress.

Runtime synchronization commences after the initial update completes and the partner is available (PAVAIL is True). The synchronization data is generated from runtime changes from the batch system (batch loaded, parameter value changed, and so on). The data is synchronized (passed to the standby) only when a change in the persistence data changes.

It is possible (although unlikely) that a batch will become Load_Failed when data synchronization has to change from one network path to another. Any network failure at the time of a Redundant Batch switchover causes the batch to be marked as Load_Failed with the reason, Redundancy Synchronization Error.

It is also possible that a batch will be Recover_Failed or Load_Failed after a switchover if the batch was created or transitioned to a new step at the same time as the switchover; or, if select persistence data is being transferred at the exact time as the switchover.

The Batch Redundancy Server manages the synchronizing of the following persisted data:

  • Registry settings

  • Arbitration data

  • Batch data

  • Recipe data

  • Batch creation data

  • Error messages

  • Step bindings

  • Batch parameter data

  • Step state data

  • Batch report parameter data

  • Step auto-selection data

  • Step run count data

  • Batch event files

  • Batch Historian journal data

  • Phase Server phase state data

  • Campaign Manager campaign data

  • Campaign Manager batch data

  • Campaign Manager recipe data
