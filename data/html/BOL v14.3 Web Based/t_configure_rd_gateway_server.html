Configure the Remote Desktop Gateway server

This procedure describes how to configure a computer to be your Remote Desktop Gateway (RD Gateway) server.

The Remote Desktop Gateway (RD Gateway) server computer is a non-DeltaV computer that resides outside of the DeltaV ACN network. Normally in the DMZ or PlantLAN (L3/L4) networks. Through this gateway, computers on non-DeltaV networks can access DeltaV (provided the credentials and certificates are valid).

  1. Install Windows Server (2008 R2 or higher) on the computer that will be your RD Gateway server and configure the network address.
    1. Using the Windows Server product disk, install the server operating system. This will require multiple reboots.
    2. Name the computer something relevant. For this example, we use the name: RDG-SRV.
    3. Configure TCP/IP properties so that RDG-SRV has an IPv4 static IP address.

      Refer to your table of IP addresses developed earlier. For this example we use the address: 10.0.0.11.

  2. Connect the RDG-SRV to the appropriate switches/hubs/firewalls (based on your network map).
  3. Join RDG-SRV to the appropriate domain (if needed).

    Because the RD Gateway computer (RDG-SRV) is normally located outside of the Emerson Smart Firewall, you would connect to a non-DeltaV network in the DMZ or higher.

  4. Install the RD Gateway role on RDG-SRV (using Server Manager).

    This will also install any dependent roles, services, and features.

  5. Provide IIS with a certificate and export a certificate for RD Gateway.

    You can create this from IIS Manager for testing/evaluation purposes.

    The type of certificate (self-signed or CA) is the user's decision. However, for TLS (Transport Layer Security) to function correctly, you must install an SSL-compatible X.509 certificate on the RD Gateway server.

  6. Install the certificate on the RD Gateway Server (RDG-SRV) using the Remote Desktop Gateway Manager.
  7. Export the SSL certificate from the RD Gateway (RDG-SRV) using Remote Desktop Manager.

    This step is only required for self-signed certificates and certificates not already trusted on the Remote Desktop Client. In those two instances, the certificate will be installed on the Remote Desktop client computer.
