Migrating displays from DeltaV Operate to DeltaV Live

Migrating displays from DeltaV Operate to DeltaV Live is accomplished in two phases:
  1. Exporting phase: In DeltaV Operate Configure, use the Export to DeltaV Live toolbar to export displays and associated graphics components from DeltaV Operate to a file system.
  2. Importing phase: In DeltaV Live Graphics Studio, use the Import command to import migrated configuration files from the file system into Graphics Studio.
The following table lists the DeltaV Operate graphics components that are migrated with a display and what they are imported as in DeltaV Live.

Note:

Scripts that are not part of DeltaV Operate Experts, as well as user forms, are not migrated into DeltaV Live.

Datalinks and text objects that have been resized in DeltaV Operate migrate as the original text (font) size. Resizing datalinks and text does not change the font size of the text and the migration process can only read the font size information (resizing information is not saved with the object in such a way as to be accessible to the migration utility).

Phase 1: Exporting displays and associated graphics components

Displays and associated graphics components are exported as individual .ahc files to the ...\DVData\Import-Export\DeltaV_Operate_Export folder. Graphics components that are used on more than one display need to be imported only once.

The export process creates a folder for each of the following items:
  • ConvertedDeltaVLiveDisplaysAndGlobals (contains all .ahc files)
  • DeltaV Operate displays and images contained on each display
  • DeltaV Operate global variables and color tables
  • iFix shape property names
Each display and global folder contains the following files:
  • Associated images
  • DeltaV Operate Expert scripting
  • Data type sizes
  • A status log file containing error, warning and informational messages, as well as known issues that might occur during the import. Each known issue also includes a recommendation for fixing the problem and an estimate of how difficult the problem will be to repair.
  • A summary log file listing the configurations and number of each configuration type exported with the display or global group. For example, the summary log may include but is not limited to data types, dynamos, tables, bitmaps, animated properties and objects, DeltaV Operate Experts, data sources, and Active X controls
  • A references log file

Phase 2: Importing migrated displays into Graphics Studio

The DeltaV Live import process imports the migrated .ahc files from the DeltaV_Operate_Export\ ConvertedDeltaVLiveDisplaysAndGlobals folder into the active DeltaV Live configuration database, placing them in the folders specified during the export from DeltaV Operate.

During and after the import process, Graphics Studio provides updating information about the progress and results of the import, which includes:
  • Importing from: Total number of items to import and number of items remaining to import.
  • Import Started: Date and time the import started
  • Import Finished: Date and time the import finished
  • The name of each item in the import
  • The DeltaV live configuration type for each item in the import
  • Import status for each item (succeeded, failed, skipped)
  • Error messages (if any) for each item
The import process creates:
  • An XML file that can be imported into DeltaV Live.
  • A status log file containing error, warning and informational messages, as well as known issues that might occur during the import.
  • A single comment added to each display by the migration software with these details:
    • User (that performed the export)
    • Date/time (when the export was done)
    • Revision
    • Display's location (assume DVDATA\Graphics-iFix\Pic\)
    • DeltaV workstation that held the display that was exported
    • Log file including path
  • A unique problem type identifier in the Description property of every element that encountered a migration issue. (For example, #Mig-0001# or #Mig-0002#.)
When the import is complete, you must resolve any migration issues that occurred during the import process. Each migration issue is indicated by the string #Mig-# and a unique problem identifier (for example, #Mig-0002#) in the affected element's Description field. Use the ribbon's Find command to find all elements with a problem identifier, find that identifier in the log file to read more details, and then resolve the issue.
