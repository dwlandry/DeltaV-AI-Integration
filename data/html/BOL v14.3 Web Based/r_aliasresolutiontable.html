Alias resolution table

Alias Resolution Table

The alias resolution table defines a list of Alias Name/Instance Definition pairs for the unit module. The list of alias names in the table is based on the valid alias names defined for the unit class. The valid alias names for the unit class, in turn, should include all alias names used in all phase classes associated with this module's unit class. This allows maximum benefit from using aliasing. The user configures the instance definition (what the alias will resolve to) for alias names that should be defined on the unit.

Note:

  There is a single master alias resolution table stored in the controller for all unit modules. Whenever the unit module or unit phase is downloaded, the alias resolution table is downloaded and updated in the controller. The new alias properties are instantiated and can affect the currently running phases.

A unit with most, but not all, of the capabilities of other units could share the same unit class but not have some alias names resolved with instance definitions in its alias resolution table. However, doing so means phase classes that use those alias names cannot be used on the unit.

To be able to have an unresolved alias in a unit, use the value IGNORE for an instance definition. IGNORE means ignore this alias's path (which can be filled in or left blank). This allows the phase algorithm that uses unresolved or null alias names to be downloaded without errors. Additionally, when the unit phase algorithm executes, the run-time IGNORE behavior is resolved as follows:

  • Write attempts are suppressed to parameters that are specified with an aliased parameter path string when the alias instance definition is IGNORE.

  • Read attempts are always successful. However, they can return an unexpected value.

Note:

When the alias instance definition is IGNORE, the parameter's IGN (ignore) field is True (1). The user must write any expressions to check the value of the parameter's IGN field and develop the logic accordingly (for example, if TEMP_PV>100 and TEMP_PV.IGN=False (or TEMP_PV.IGN=0), then Reduce Heat).

The correct syntax for referencing an alias's IGNORE field is '/ALIAS.IGN' (for example, 'READ_IGN.CV' := '/ALIAS1.IGN').

You must select the Ignore check box on the Alias dialog to give the alias the value IGNORE. Leaving the parameter reference path blank will result in errors when verifying the unit module.
