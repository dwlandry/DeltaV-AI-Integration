Zones hardware architecture

The hardware implementation of DeltaV Zones requires the addition of an Inter-Zone Server (IZS) in each DeltaV system. The Inter-Zone Servers are then connected by an Inter-Zone Control Network (IZCN). The only function of the Inter-Zone Servers and their network is to communicate Inter-Zone operating data between systems.

Each IZS node must have:

  • a network interface connection (NIC) (two for redundant communications) for DeltaV network
  • a network interface connection (two for redundant communications) for the Inter-Zone Control Network

The following figure shows a simple example of a DeltaV Zones implementation connecting two DeltaV systems. The purpose of this diagram is to show how the Inter-Zone Servers connect to the DeltaV network and to each other. The diagram is not intended to be a recommended configuration.

Simple example of a Zones system

As the figure shows, a DeltaV zone is a DeltaV system that includes an Inter-Zone Server. That is the only difference between a zone and a system.

Note:

Redundant IZSs switch over only when DeltaV ACN network communication is lost. Redundant IZSs do not switch over when Inter-zone communication is lost. Verify that zones are communicating by monitoring the zone and IZS integrity diagnostics parameters or assigning these integrity parameters to alarms.

Note:

In systems with redundant Inter-Zone Servers, there is a loss of communications for several seconds after an IZS switchover occurs. During this delay, external references in modules are affected. The .CV values are Hold Last Value and .ST values are BadNoCommLUV (numeric value 24). This delay can last as long as 30 seconds.

You should consider this delay when configuring control strategies with control across zones.

Redundant Inter-Zone Control Network with Plant LAN

After implementing DeltaV Zones you can perform non-control functions between DeltaV systems using standard Windows network support functions over a separate plant or non-control network. The DeltaV workstations that use the plant network must have sufficient Domain trust relationships in place. All workstation names must be unique among all connected DeltaV systems (no duplicate workstation names anywhere within the zones).

Interconnected zone hardware must all be in the same time zone and have the same installed language choice.

The only DeltaV menu options on an IZS are:

  • Engineering > FlexLock > Floating License Manager
  • Help > Books Online
  • Operator > DeltaV Login

If your DeltaV systems are configured as workgroups and you need to add users who can log in to the IZS, do the following:

  1. From the DeltaV User Manager on another workstation in the system, create the users.
  2. Use Replicate Account to copy the account to the IZS.
  3. Close the DeltaV User Manager.
  4. Download the workstation.
  5. Download the IZS.

The user accounts now exist in the IZS.

Note: If you are connecting DeltaV systems that are configured as domains, each system must have a unique domain name.
