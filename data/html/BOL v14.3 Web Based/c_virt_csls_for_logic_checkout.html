SIS CSLS logic checkout using virtual machines

You can test the configuration and logic of a SIS CSLS system without physical hardware by creating a test DeltaV system using the DeltaV virtual machine (VM) templates of the SZ controller, the CHARMs Smart Logic Solver (CSLS), and the Local Safety Network Bridge (LSNB). Use these templates with DeltaV Virtual Studio (DVS) to create test systems.

All of the SIS CSLS hardware in a test system using VMs must be virtual machines, but depending on your requirements and situation, you may need or want some physical hardware in your system, for example, Global Safety Networks, ACNs, and the ProfessionalPLUS workstation. The information in this document applies whether these items are physical or virtual. This document uses the term virtual system to refer to the test system that is a collection of physical and virtual items used for logic checkout.

The following are necessary to use virtual machines to check out SIS CSLS logic:

  • An adequate number of Virtual Machine host computers to support the virtual machines to be configured in the virtual system are available.
  • DeltaV Virtual Studio is available.
  • The virtual system is not connected to a production system.
  • The VM templates you need are accessible from DeltaV Virtual Studio.

The use of SIS CSLS VMs as described in this document is constrained by the following:

  • A virtual system supports checking of configuration logic only. It does not support simulation systems or operator training systems.
  • If you are using the recommended and supported computers, each VM host supports as many as 18 virtual machines. For example, one VM host can contain an entire virtual Local Safety Network (one SZ controller, 16 CSLSs, and one LSNB) or any combination of SZ controllers, CSLSs and LSNBs as long as the total number of VMs does not exceed 18.
  • You cannot combine virtual and physical SIS CSLS hardware in a system.
  • Simulated I/O is not supported but you can use the SIMULATE_IN parameter at the function block level. You can also use Debug mode.
  • The entire DeltaV system must be exported and imported to ensure module CRCs are unchanged.
    Note:

    If the same ProfessionalPLUS workstation is used in the virtual system and the physical system you do not need to export and import the DeltaV system. You need only to unassign the CSLSs and SZs from the virtual nodes to the physical nodes.

  • The ProfessionalPlus workstation name should be the same in the virtual system and the production system. (This is not an absolute requirement but if the names are the same there is less clean up required after importing to the production system.)
  • Only if the instructions in this document are followed will module CRCs remain unchanged when the configuration is moved from the virtual system to the production DeltaV system.
