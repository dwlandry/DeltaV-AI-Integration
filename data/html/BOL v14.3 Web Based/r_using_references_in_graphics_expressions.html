Using references in graphics expressions

Graphics expressions can reference the following values:
  • DeltaV parameters
  • Library standards
  • Library functions
  • Properties in a containing layout, display, group, or GEM
  • Graphics variables in a containing layout, display, group, or GEM

Referencing DeltaV parameters (using DeltaV Live path syntax)

When you reference DeltaV parameters in a graphics expression, use the DLSYS object and the following syntax: 
DLSYS[<graphics expression>]
where:
  • DLSYS is a mandatory and case-sensitive prefix that reads and evaluates DeltaV parameter field values through DeltaV Live path syntax.
  • <graphics expression> contains a <DeltaV parameter path string> and can contain an optional <read-as suffix>, where:
    • <DeltaV parameter path string> is a fully resolved path referencing a DeltaV parameter.
    • <read-as suffix> controls how DeltaV parameters are read, and thus determines whether the expression returns a string (.str) or floating point value (.flt).

      For example, when an alarm's .PRI field is read as a string, it returns the configured priority word; but when read as a number, the .PRI field returns the configured numeric priority value.

      To force a reference to return a string value, use the (.str) prefix (case-insensitive). To force a reference to return a float value, use the (.flt) prefix (case-insensitive).
        

The following rules determine whether references to DeltaV parameter fields resolve to a floating point value or string:
  1. If the <read-as suffix> is included in the expression, it determines whether the parameter field is read and returned as a string or float value.
  2. If the <read-as suffix> is not present, and the expression is configured for the property of a string, mode, or named set-type DataLink element, the parameter field is read as a string and returns a string value.
  3. Otherwise, the parameter field is read and returned as a floating point number.
The following table provides examples of graphics expressions that reference a DeltaV parameter:
Syntax example This example...
DLSYS["FIC101/PID1/PV"] Returns the process value for the PID1 function block on the FIC101 module, in this DeltaV system, as a floating point value.
DLSYS["FIC101/PID1/MODE.TARGET.STR"] Reads the Target Mode for the PID1 function block on the FIC101 module, in this DeltaV system, as a string, and then returns it as a string.
DLSYS["PDT1/FAILED_ALM.PRI.Flt"] Reads the FAILED_ALM alarm priority as a floating point value, for the PDT1 ??, in this DeltaV system, and then returns it as a floating point value.
DLSYS["FIC101/SGCR1/CURVE_X[3].CV"] Returns the current value of CURVE_X for the SGCR1 block on the FIC101 module, in this DeltaV system, and returns it as a floating point value.
DLSYS[Grp.ModuleName + "/PID1/SP.FLT"] The set point for the PID1 block on the ??? module belonging to the nearest containing group, in this DeltaV system, and returns it as a floating point value.

Referencing DeltaV parameters (using DeltaV Operate path syntax)

When you reference DeltaV parameters using DeltaV Operate path syntax, use the DVSYS object and the following syntax: 
DVSYS[<legacy DVSYS data reference>]
where:
  • DVSYS is a mandatory and case-sensitive prefix that reads and evaluates DeltaV parameter field values through DeltaV Operate path syntax.
  • <legacy DVSYS data reference> is a fully resolved path referencing a DeltaV parameter.

Referencing standard and library functions

When you reference a standard or library function in a graphics expression, use the syntax 
GL.<Library name>.<Library item name>
where:
  • GL. is a required and case-sensitive prefix holding the configuration libraries.
  • <Library name> is the name of one of the configuration libraries present in the system.
  • <Library item name> is the name of the standard or library function within the <Library name>.
The following table provides examples of graphics expressions that reference standard or library functions:
Syntax example This example retrieves...
GL.Library1.Red The standard named Red from the configuration library named Library1.
GL. Library1.Measurement1 The standard named Measurement1 from the configuration library named Library1.
GL.Library2.Number1 The standard named Number1 from the configuration library named Library2.
GL.Library1.F_Chart_Resize The library function named F_Chart_Resize from the configuration library named Library1.
GL. Library1.PumpValveFillColor The library function named PumpValveFillColor from the configuration library named Library1.
GL.Library2.SISStatusVisibility The library function named SISStatusVisibility from the configuration library named Library2.
References to library items become unresolvable when any of the following conditions are true:
  • The item (identified by its <library name>.<library item name>) does not exist in the specified Library.
  • The item exists but has a return value type incompatible with the animated property.
  • (For library functions only): The item exists but the actual arguments are not sufficient for the library function's inputs.
When a reference to a library item cannot be resolved, or it resolves to an unsupported type, the graphics expression returns an empty string. These conditions may occur when deleting or importing graphics configurations. However, if you create a new item (of the same type) with a name matching the deleted or imported one, the reference resolves without the need to publish.
Note: The properties that reference a standard or library function are linked to it; therefore, when you modify a standard or library function, all properties referencing that standard or function reflect the change.

Referencing properties and variables in a containing group, GEM, or display

When you reference properties or variables in a graphics expression, you must use a case-sensitive prefix to establish the context for resolving the reference.

These expressions use one of the following syntax:
  • Lyt.<PropertyName/VariableName>, where Lyt. establishes that the variable or property is defined in the current running layout.
  • Dsp.<PropertyName/VariableName>, where Dsp. establishes that the variable or property is part of the containing display where the expression is configured.
  • Grp.<PropertyName/VariableName>, where Grp. establishes that the variable or property belongs to the nearest containing group where the expression is configured.
  • Gem.<PropertyName/VariableName>, where Gem. establishes that the variable or property is also in the GEM class where the expression is configured.
The following table provides examples of graphics expressions referencing a property or variable in a containing layout, display, group, or GEM.
Syntax example This example...
Grp.<ModuleName> belonging to the nearest containing group
Gem.<??> belonging to the nearest containing GEM
Dsp.<??> belonging to the nearest containing display
Lyt.<??> belonging to the nearest containing layout
