Report parameter resynchronization

The following lists how changes to recipe report parameters affect warm and cold restarts with resynchronization.

Modifying Active Steps, Warm Restart

  • Modifying recipe report parameters on active steps causes warm restart with resynchronization to fail.

  • Changing the recipe report parameter type (integer, real, named set or string) causes warm and cold restart with resynchronization to fail.

Modifying Active Steps, Cold Restart

  • Changing the recipe report parameter type (integer, real, named set or string) causes warm and cold restart with resynchronization to fail.

  • Modifying recipe report parameters on active steps succeeds with cold restart with resynchronization, except in the case of changing the parameter type (integer, real, named set, or string), which fails resynchronization.

Inactive Steps, Value Not Uploaded, Warm and Cold Restart

  • Changing the recipe report parameter type (integer, real, named set or string) causes warm and cold restart with resynchronization to fail.

  • Modifying recipe report parameters on inactive steps succeeds with warm and cold restart with resynchronization, except in the case of changing the parameter type (integer, real, named set, or string), which always fails resynchronization.

Inactive Steps, Value Uploaded, Warm and Cold Restart

  • Changing the recipe report parameter type (integer, real, named set or string) causes warm and cold restart with resynchronization to fail.

  • Changing recipe report parameters causes warm and cold restart with resynchronization to fail except in the following two conditions:  

    • Changing an input parameter's origin from Value or Operator to Defer and deferring it to a report parameter succeeds

    • Changing an input parameter to a report parameter (that is, deleting the input parameter and adding a report parameter of the same name).
