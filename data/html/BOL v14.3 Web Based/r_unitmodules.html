Unit modules

The unit module is an instance of a unit class and defines all of the variables and phases for a single process unit. Typically, the names identify specific process equipment that an operator would recognize (for example, unit modules might be named FEEDHEADER_01, REACTOR_01, DRYER_01, and so on).

The unit module is used with the phase algorithm definition and is an instance of a unit class. In this manner, the unit module provides the environment for the logic to run in the controller.

Note:

The unit module design must be used when utilizing the DeltaV Batch aliasing features.

Example Unit Module

A unit module has the following:

  • Unit parameters with initial values. The default initial values are derived from the unit parameter definition configuration (at the unit class level) when the unit module is created. They can be changed to be specific to a unit.

Note:

Parameters cannot be created at the unit module level. Any parameters used by the unit module must be created in the unit class.

  • One alias resolution table.

  • One phase table.

  • Standard alarms (for example, phase algorithm failures for active phases or for phases that run beyond a predetermined length of time).

The following are required to define a unit module:

  • Resource ID

  • Maximum number of owners

  • Control display (MMI picture)

  • Resources that the unit requires

  • Inclusion in Process Cell

The unit module is a member of and is based on a single unit class. Unit modules also have standard DeltaV control module behavior, such as:

  • Belonging to a plant area (and process cell).

  • Being assigned to a node that has a control subsystem and can subsequently be downloaded.

Note:

License checks require assigning unit modules to controllers that have batch level control licenses.

  • Having parameters that are addressed in the run-time system by unit module name.

Unit module names have the same naming rules as other modules and must obey the same naming rules as units. When renaming a unit module, you must also make some change to the recipe that uses the renamed unit module and save the recipe. This timestamps the recipe.dir file with a newer date/time and allows the download the Batch Executive to update the recipe so the new unit module name is used.

Note:

The user must select either phase logic modules or unit-based phase algorithms as the logic development method.

The following rules apply to configurations using unit modules:

  • Unit modules are a superset of units, with respect to configurable properties.

  • It is not possible to create a phase logic module as a subordinate of a unit module. Unit modules use unit phases as instances of the phase logic.

  • It is possible to have a unit phase shared by multiple unit modules. Unit modules in the same unit class share the same phase classes; therefore, they share unit phases.

  • It is possible to create an external phase as a subordinate of a unit module.

  • It is not possible to split a single unit module (specifically, the unit phases possible to run in a unit module) across multiple nodes.

  • The initial values for phase parameters are configured in the phase class. The phase parameters, complete with initial values, are instantiated in all units associated with the phase class. Distinct per unit parameter values must come from either unit module-level parameters, which come from unit parameter definitions or from a recipe design that only runs on that unit.

  • The $AVAILABLE parameter must be set to a non-zero value before deleting a unit module that was assigned to a controller.

Unit modules have two components that may or may not be downloaded at one time.

  • The unit module (unit phase table, alias resolution table, parameters, alarms, and so on)

  • The unit phases

When downloading the unit module from the unit module level, DeltaV Explorer always downloads the module items, that is, parameters, unit phase table, alias resolution table, alarms, and so on. Contained modules (such as equipment modules and control modules) are downloaded on their own as separate download items.

When a unit module is downloaded the first time, the valid unit phases are downloaded if they do not already exist in the controller. That is, the unit phases are not valid on any other unit modules that have already been downloaded to the controller.

Any time the unit phase is changed and a unit module download is selected, the entire unit module is downloaded to the controller. The download process compares the existing unit phase with the one about to be downloaded, if there is a difference, the unit phase is included in the download. When a changed unit phase is downloaded, all unit modules in that controller will use the newly downloaded unit phase when run. If the unit phase being downloaded is currently loaded (running), that instance will continue running using the starting unit phase definition. The next time the unit phase loads (runs), it will use the new definition.

However, if the unit phase does not have the phase type set to Controller, the unit phase is not downloaded with the unit module.

Note:

The unit phase can be downloaded independently of the unit module, however, the unit phase table and unit parameters cannot. To download only the unit phase, open DeltaV Explorer. From the appropriate area, expand the unit module. Select the unit phase, right-click, and then select Download Unit Phase.
