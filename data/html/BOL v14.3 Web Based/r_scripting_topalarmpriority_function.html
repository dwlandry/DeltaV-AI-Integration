TopAlarmPriority function

The TopAlarmPriority function returns the priority level of the top active or unacknowledged alarms that are associated with the designated display.
Arguments
1–2, Optional arguments are indicated by a ? following the argument name.
Argument Description
DisplayName A literal or graphics expression that resolves to the name of a display.
[ChildDisplays] A literal or graphics expression whose value is interpreted as true or false. When evaluated to:

True, the return count includes active or unacknowledged alarms for the specified display, as well as from all direct and indirect child displays of the specified display in the display set.

False, the return count includes active or unacknowledged alarms in only modules, nodes, and devices whose primary control display is the specified display.

If this argument is omitted or undefined, the assumed value is false.

Return values (number)
The top alarm priority, according to the most important to see by alarm banner sorting rules, of all active or unacknowledged alarms satisfying the argument criteria.
3 (log priority level), if the specified primary control display has no active or unacknowledged alarms associated with it.
0 with a bad data quality status, if DisplayName cannot be resolved.
Syntax
DARU.TopAlarmPriority(DisplayName, ChildDisplays)
Examples
Example Result 
DARU.TopAlarmPriority(DL.DN("Reactor1"))
 Shows the top alarm priority of all active or unacknowledged alarms associated with the Reactor1 display. 
DARU.TopAlarmPriority(Gem.DisplayName, true)
 Shows the top alarm priority of all active or unacknowledged alarms associated with the associated with the ??? display and its child displays.
Note:
  • The value returned is not necessarily the maximum priority level of all alarms matching the criteria. For example, according to the sorting rules for an alarm banner, an unacknowledged priority level 11 alarm is more important to see in the alarm banner than an acknowledged level 15 alarm. Therefore, the value returned is 11 rather than 15.
  • It is recommended that you use the DL.DN() function for enabling display rename tracking when the DisplayName argument is a literal string.
