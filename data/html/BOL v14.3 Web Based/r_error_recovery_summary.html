CSLS error and response summary

The following table summarizes the evidence and action needed when the various classes of errors (fatal and non-fatal) occur in simplex and redundant CSLSs. The table shows the state of alarm and diagnostic parameters approximately five minutes after the error is detected.

Summary of the Evidence of CSLS Errors and the Needed Action
Error Type Simplex CSLS Redundant CSLS
Evidence Action Evidence Action

Non-Fatal,
Momentary

Inact-Unack alarm
(MAINT and/or ADVISE)

Acknowledge the alarm(s).

Check Event Chronicle records to determine error condition.

Record error occurrence; report to Emerson if there is a repeat occurrence.

(error on active and /or standby CSLS unit)

Inact-Unack alarm
(MAINT and/or ADVISE)

Acknowledge the alarm(s).

Check Event Chronicle records to determine error condition and affected CSLS unit(s).

Record error occurrence; report to Emerson if there is a repeat occurrence.

Non-Fatal,
Persistent

Act-Unack alarm
(MAINT and/or ADVISE)

Acknowledge the alarm(s).

Check _ALERTS parameter associated with alarm to determine error condition.

Report error to Emerson.

(error on active and /or standby CSLS unit)

Act-Unack alarm
(MAINT and/or ADVISE)

Acknowledge the alarm(s).

Check _ALERTS parameter associated with alarm to determine error condition.

Check _STATUS parameters on both CSLS units to determine affected one.

Report error to Emerson.

Momentary

Inact-Unack
COMM_ALM

Acknowledge the alarm.

Restart the process at the appropriate time.

Check PAST_ERROR on card to determine error condition.

Report error to Emerson.

MAINT_ALM

Report error to Emerson.
