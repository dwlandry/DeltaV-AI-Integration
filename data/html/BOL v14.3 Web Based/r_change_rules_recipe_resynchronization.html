Change rules for recipe resynchronization

There are limitations to the configuration changes that are acceptable for recipe resynchronization, especially when warm restarting. If the limitations are surpassed, the resynchronization will fail (the batch can still be restarted; however, the changes will not take affect).

The following limitations ensure a successful recipe resynchronization:

  • Warm restarting a recipe validates the initial settings of the recipe and the active items; therefore, you cannot invalidate anything that the recipe initially used nor any active steps or transitions, particularly the following:

    • Units that were valid when the recipe was created must still be valid when resynchronizing the recipe.

    • Active steps cannot be reordered such that the active step is not followed by the active transition (cannot switch the active step to be after the active transition).

    • A step cannot be inserted between any active step and the active transition.

    • Active steps cannot be modified, or deleted (including equipment changes, alias definitions and so on).

    • Active transitions cannot be reordered such that the active transition no longer follows the active step.

    • A transition cannot be inserted between any active step and the active transition.

    • Active transitions cannot be modified or deleted.

  • Link groups cannot be changed.

  • Procedures can have a new step added. That new step starts with its equipment set to its instance unit if instance based, its Alias if alias based, or {defer} if class based.

  • Any unit or unit class being used by the batch must still exist when performing a warm restart with resync.

  • Aliases associated with the Unit Procedure steps in the recipe must remain. Aliases can be modified provided the modification does not cause the active step to be changed.

  • Batch report parameter types cannot be changed. A change in type for a report parameter will cause the recipe resynchronization to fail when the option to verify. report parameters is enabled (the default setting is enabled).

  • Batch input parameter type changes can cause the recipe resynchronization to fail. Caution should be used if deleting and re-adding parameters with the same name. The Parameter Values Resynchronization Chart topic details how input parameter values are resynchronized for both warm and cold restarts.

  • Recipe report parameter changes can cause the recipe resynchronization to fail. Caution should be used in making changes. The Report Parameter Resynchronization topic details how report parameter changes affect resynchronizing recipes for both warm and cold restarts.

  • Equipment trains can be modified provided the modification does not cause the active step to change, does not remove an alias being used by the batch, and does not become invalid for the recipe. 

    Note:

    If the equipment train's valid units are changed from multiple units to one unit, and the alias is currently set to defer in the batch, the remaining unit is assigned as part of the resynchronization.

  • Unit alias selection mode changes are valid (however, changes from Defer to From_Policy are ignored during resynchronization). Unit alias selection mode changes are incorporated for all unassigned aliases on associated steps as they execute.

  • On warm restart with resynchronization, a selection mode change of From_Policy to Defer affects all steps where the unit has not been selected prior to resynchronization. The operator is prompted after resynchronization for any units that were previously assigned that now fail validation. Initial selection mode changes (to the unit alias in the equipment train class) are incorporated for all unassigned aliases on steps as they execute.

  • Downstream unit information (either downstream units or downstream unit aliases) can be modified. The operator is prompted after resynchronization for any units that were previously assigned that now fail validation. Unassigned unit aliases are assigned according to the changed configuration after resynchronization.

  • Unit selection policy changes only affect unassigned aliases with a selection mode of From_Policy. The operator is not prompted on any units that were already assigned by policy selection. Unassigned unit aliases are selected according to the changed unit selection policy after resynchronization.

  • Any change must pass recipe validation.

  • Any change that would fail a warm or cold restart without resynchronization will also fail a warm or cold restart with resync. If the resynchronization fails, the batch goes to Recover_Failed and can be restarted. No changes are made to the recipe.
