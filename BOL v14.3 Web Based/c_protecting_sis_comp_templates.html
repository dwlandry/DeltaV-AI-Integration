Protected SIS composite templates

The protection available for individual SIS Composite Templates has a different purpose than the protection of the SIS Composite Templates categories. There are three protection-related items on the menu for SIS Composite Templates in DeltaV Explorer:

  • Unprotect Template — Remove the protection for the selected template. If the template was protected with a password, you must enter the current password unless you have DeltaV Administrator privileges.

  • Change Template password — Change the current password for the selected template.

  • Protect Template — Apply protection to the template, with or without a password.

You must have the SIS Can Configure key to perform any of these tasks.

A protected SIS Composite Template can be modified only on a DeltaV system that has the DeltaV System ID of the system where it was originally protected (the source system) and then only if a user has sufficient privilege to unprotect it. A template that has been protected on one system and then deployed to another DeltaV system (the target system) cannot be unprotected or modified on the target system in any way. A protected template on a target system can only be deleted, and then only if the template is not used in any module.

Use protected SIS Composite Templates to prevent unauthorized changes to your engineering standards for SIS Composite Templates. An SIS Composite Template configured and debugged at one engineering location can be protected (with or without a password) before distribution for use at other engineering locations. Distribution is by the standard DeltaV export functionality. The .fhx file created from a protected SIS Composite Template is encrypted to ensure that it cannot be modified by any means on target systems. 

Implement SIS Composite Templates as Embedded Composites in SIS Modules. The contents of an Embedded Composite created from a protected SIS Composite Template cannot be edited except for:

  • You can override values of the Embedded Composite that have been promoted to the SIS composite level. 

  • You can edit the description parameters of the Advanced function blocks.

An Embedded Composite that is protected cannot be unprotected in the SIS Module.

The functionality of protecting SIS Composite Templates interacts with the protection available at the SIS Composite Template category level. It is not possible to:

  • Protect a Category if it has protected SIS Composite Templates in it.

  • Protect an existing SIS Composite Template if it is in a protected Category.

  • Create an SIS Composite Template in a protected Category by any means, such as:

    • Import from an .fhx file or from Bulk Edit

    • Cut/Copy/Paste

    • Drag/Drop

If you use protected SIS Composite Templates there are a couple of recommended practices:

  • Before exporting an SIS Composite Template, record the CRC value. Import the template to the target system and record its CRC value. The CRC values should be identical.

  • Make a backup copy of the Protected SIS Composite Templates.

With this saved information you can troubleshoot problems related to Protected SIS Composite Templates or restore the configuration.

Note:

In SLS 1508 systems, all logic solvers must be updated to firmware revision 3.1.0.x or greater for Protected SIS Composite Templates to work as intended.

If you add module-level parameters to write to internal parameters in a protected composite, make sure to add the parameter names in SIS parameter security or change the default lock for SIS parameters.
