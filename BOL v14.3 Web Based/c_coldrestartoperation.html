Cold restart operation

Note:

The loss of power to a controller and a subsequent cold restart or user restart can be disruptive to the process. An uninterruptible power supply (UPS) is highly recommended as a means to prevent process disruption during a short power loss.

Cold restart actions common to all controller types

The system provides download data in script format. When you request a download, the system sends the download script to the controller. You can determine where a cold restart source is by opening DeltaV Diagnostics, selecting the controller, then selecting Restart > ColdStrtSrc.

The system also saves the download script in the \POWERUP directory on the ProfessionalPLUS workstation. In the event of a power loss, the controller can restart using the download script in cold restart memory (if available). The restart process is relatively fast and does not require communication with the ProfessionalPLUS workstation. If the cold restart memory is not available, communication with the ProfessionalPLUS workstation is required so that the restart process can get the download scripts from the \POWERUP directory.

You can check the validity of the \POWERUP directory through the PowerUp Directory Test command under the Tools menu in the Diagnostics application.

You can schedule a backup of the \POWERUP directory through the Daily PowerUp Directory Backup tool in the Database Administration application.

You enable the cold restart feature on the Controller tab of the Node Properties dialog in DeltaV Explorer. To specify a time, select Enabled Within A Time Limit and enter Time Limit values. To set the Time Limit to the maximum (approximately one month), select Always Enabled (maximum time). To disable this feature, select Always Disable.

When power is restored the controller goes into the COLDRESTART state. However, if the specified time elapses before power is restored, the controller goes into the USERRESTART state. This state requires you to download the controller node from the Explorer.

You can update the cold restart memory and ensure CldStrtSrc is the controller using the Download > Controller Cold Restart Memory command or performing a total download in DeltaV Explorer.

MX, MQ, SQ, SX, SZ, and PK controller cold restart actions

The cold restart information is saved in the controller during the download. ColdStrtSrc is always the controller.

The system clears cold restart memory in response to the following operations:

  • Controller upgrade (the system saves the cold restart information during the download)

  • Decommission/commission

  • Total and partial downloads: A total download replaces the existing cold restart information with the new download. A partial download changes only what is new in the download.

MD Plus and SD Plus controller cold restart actions

Immediately after the download, the system downloads the total download script to the controller cold restart memory.

If the system is transferring a download to the cold restart memory and you request a second download before the transfer is complete, the system cancels the transfer and logs a Cold start memory download is preempted or Cold restart download items rejected event. The system then transfers the second download to cold restart memory.

The system clears cold restart memory in response to the following operations:

  • Controller upgrade (the system automatically initiates a Controller Cold Restart Memory download following the total or partial download)

  • Decommission/commission

  • Upload

  • Total and partial download (the system automatically initiates a Controller Cold Restart Memory download following the total or partial download)
