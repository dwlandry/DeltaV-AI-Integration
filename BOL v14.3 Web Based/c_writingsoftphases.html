Writing soft phases

To write a soft phase, use one of the templates by running CreateSoftPhase.exe (found in the soft phase installed directory's \Bin folder). In the application choose the development environment and name the soft phase.

Create Soft Phase application dialog

The CreateSoftPhase application creates a new project in the SRC\*name* (where *name* is the name you gave the soft phase) directory. This project contains all the items needed to create a soft phase executable. Add the code you need for the Run, Hold, Stop, Abort and Restart methods and build the executable. The executables (which are the soft phases) are saved in the \Bin directory where the Soft Phase Broker, Soft Phase Tester, and Soft Phase Server can locate them.

The following important items should be considered before creating your soft phase.

  • It is strongly recommended that the person writing the soft phase have programming experience in either Visual C++, C++ .NET, Visual Basic, or Visual Basic .NET and is familiar with the language's syntax and the environment's structure.

  • Creating a soft phase using multithreading requires careful handling of thread concurrency. It is strongly advised that the person writing the soft phase have programming knowledge and experience with mutual exclusions AND that the soft phase be thoroughly tested before running in a plant environment.

  • Use the SoftPhase DebugMessage API very sparingly in your runtime/production environment version of soft phases. The DebugMessage API is intended for assisting with developing soft phases and consumes resources in the soft phase server. To obtain runtime status information, the soft phase can create its own log files or use the Windows Event Viewer.

  • When writing soft phases, you should not generate Windows dialogs from the soft phase. However, you can use the phase request codes for operator prompts (30nn, 31nn, 32nn, 33nn, 34nn, and 35nn) that are displayed in the Batch Operator Interface.

Note:

When opening a .NET soft phase in Visual Studio 2005 or newer, Visual Studio runs a conversion utility to migrate the soft phase to the current version of Visual Studio. After this conversion process, it is up to you to verify that the soft phase will run as expected.
