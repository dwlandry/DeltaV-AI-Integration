Wireless I/O troubleshooting

There are several ways to troubleshoot Wireless I/O:

  • The controller's COMM_ALM hardware alarm condition becomes active if the controller cannot communicate with an assigned Gateway. For redundant controllers, the COMM_ALM hardware alarm condition becomes active if it cannot communicate with an assigned Gateway on both networks.

  • If device alarms are enabled on a wireless device, alarms under the device tag become active when there are active alert conditions in the device.

  • If a Wireless Gateway loses communication with the DeltaV system, a red X appears on the Gateway's icon in DeltaV Explorer and in DeltaV Diagnostics.

  • Use the Gateway's web interface to gather diagnostic information about the network. To launch the Web Interface, select a commissioned Wireless Gateway node and select 1420 Web Interface from the context menu.

  • Use the DeltaV Diagnostics application. To launch Diagnostics click Start > DeltaV Operator > Diagnostics.

  • Use the troubleshooting information provided in the 1420 documentation.
