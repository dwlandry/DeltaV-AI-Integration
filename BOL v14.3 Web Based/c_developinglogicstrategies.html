Developing logic strategies

It is important to start developing a strategy for implementing phase logic early in the process. With the DeltaV Batch subsystem, the overall strategies can be class based so that duplication is not needed to run the same recipe on several units.

Where units are of the same type, class-based design saves a lot of time and effort. Where there are substantial differences between units, although the functions are the same, more development time is required to accommodate differences. For example, suppose you want to use the same unit class for several reactors, but some have mechanical agitators and others have bubbler agitation. If you use a phase class AGITATE for both types of units, the associated phase logic must have the same parameters, even though they are not equivalent. In this case, you must decide whether the time savings for class-based recipe development will make up for the extra development time and complexity in developing the equipment logic.

DeltaV Batch provides two methodologies for creating class-based phase logic; unit modules that use unit phases or units that use phase logic modules. However, unit modules are the most effective method for creating class-based logic.

Logic Strategy Using Unit Modules

When using unit modules, you can use the aliasing function of DeltaV Batch to streamline class-based design.

First, create the unit class with the common features for an agitator tank. Then, define the aliases to be used on agitator tanks. Instantiate the unit class in the area. This creates a unit module that inherits all the properties (alias list, unit parameters, and so on). Next, create the phase class AGITATE. Define the valid aliases for this phase class. The valid aliases should include the alias list created for the unit class of agitator tanks. Now, when you create an instance of the phase class on the unit module, a unit phase results containing a phase algorithm. This phase algorithm inherits the properties of the phase class, including algorithm parameters and the valid alias list. The unit phase resolves the aliases at runtime, depending on the agitator tank selected.

This means the logic for agitation is defined once, no matter which agitator in that class is used.

Logic Strategy Using Phase Logic Modules

When using phase logic modules, you should create the phase class to encompass all the shared Batch Input/Report Parameters and Phase Messages requirements of a process. However, the Phase Logic Modules do not support Phase Algorithm Parameters, and the phase logic is not inherited from the Phase Class. Only one member of a phase class can be included in a unit. If you want to use class-based recipes, you must include the members of the same phase classes in all units of the unit class.
