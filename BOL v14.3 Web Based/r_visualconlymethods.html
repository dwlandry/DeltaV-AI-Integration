Visual C++ only methods

Visual C++ Only Methods

Note:

Be sure to set the Visual C++ Active Project Configuration to "release" configuration when compiling instead of the default setting "debug". If Soft Phase is compiled as a debug configuration, some methods will cause problems when they are executed.

  • ReadAttributeLong - Allows user to read values as a long rather than having to deal with Variants. Takes two parameters, a string containing the attribute name and a reference to a long in which the value is returned.

  • ReadAttributeFloat - Allows user to read values as a float rather than having to deal with Variants. Takes two parameters, a string containing the attribute name and a reference to a float in which the value is returned.

  • ReadAttributeString - This is a deprecated method. Using it will cause the soft phase to fail (fail index of 255). This method has been replaced by ReadAttributeStringA and ReadAttributeStringW.

  • ReadAttributeStringA - Allows user to read values as an ANSI string rather than having to deal with Variants. Takes two parameters, a string containing the attribute name and a pointer to an ANSI string in which the value is returned. This method will allocate memory. The user must free the memory using CoTaskMemFree.

  • ReadAttributeStringW - Allows user to read values as a UNICODE string rather than having to deal with Variants. Takes two parameters, a string containing the attribute name and a pointer to a UNICODE string in which the value is returned. This method will allocate memory. The user must free the memory using CoTaskMemFree.

  • WriteAttributeLong - Allows user to write values as a long rather than having to deal with Variants. Takes two parameters, a string containing the attribute name and a long containing the value to write.

  • WriteAttributeFloat - Allows user to write values as a float rather than having to deal with Variants. Takes two parameters, a string containing the attribute name and a float containing the value to write.

  • WriteAttributeString - This is a deprecated method and using it will cause the soft phase to fail (fail index of 255).This method has been replaced by WriteAttributeStringA and WriteAttributeStringW.

  • WriteAttributeStringA - Allows user to write values as an ANSI string rather than having to deal with Variants. Takes two parameters, a string containing the attribute name and an ANSI string containing the value to write.

  • WriteAttributeStringW - Allows user to write values as a UNICODE string rather than having to deal with Variants. Takes two parameters, a string containing the attribute name and a UNICODE string containing the value to write.

  • LockThread - This allows the user to prevent the DLL from suspending the run logic. This is used when the run logic is doing a group of actions that should not be interrupted. The thread should then unlocked once the group of actions is complete. It takes one parameter which is a timeout period. If the DLL finds the thread is locked it will wait for the timeout period for the thread to be unlocked before it goes ahead and suspends it. If the timeout period is 0 then DLL will simply wait until the thread is unlocked.

  • UnlockThread - Unlocks the thread once the run logic is in a state where it can be interrupted.

  • DebugMessageW - Same as DebugMessage except it takes a UNICODE character string as a parameter.
