The Campaign Manager components

The DeltaV Campaign Manager is composed of several software modules that work together to form a classic client/server-based, distributed application.

Note:

All nodes have to be part of the same domain or workgroup.

The major components are as follows:

DeltaV Batch Campaign Manager Operator Interface

This client application supplied with the DeltaV Campaign Manager product allows end-users to define and manipulate campaigns along with the individual batches within a given campaign. This includes selecting recipes, formulas, unit binding, and parameter information for each batch within a campaign (as well as the campaign itself) as well as releasing, starting, and removing batches to the Batch Executive.

The client application can be installed and used on any Windows workstation or Windows server operating system that is currently supported for DeltaV, even if the computer is not a DeltaV computer.

DeltaV Batch Campaign Manager Client Control

The Campaign Manager client control is a standard ActiveX control that provides all client applications (including the one provided with the DeltaV Campaign Manager product) with a programmable API (Application Programming Interface) to the Campaign Manager server. This API can be programmed against from a variety of environments, including C\C++, and VB.

Like the client application, the client control can be run on any Windows workstation or Windows server operating system that is currently supported for DeltaV, even if the computer is not a DeltaV computer.

DeltaV Batch Campaign Manager Server

The Campaign Manager server provides all Campaign Manager clients with a single point of entry for all campaign-related information. It is responsible for both maintaining and monitoring all of the campaigns defined throughout the system along with all of the batches within the campaigns. The Campaign Manager server communicates with the Batch Executive to allow limited control of batches (release, start, and remove) and to keep track of various batch states, for example, RUNNING, STOPPING, HELD, and so on.

Running Controls on an Non-DeltaV Node

To run the Campaign Manager Operator Interface or Campaign Manager client control on a non-DeltaV node, you must perform the following steps:

  • Register the files, dvbcampaignmgrps.dll and dvbctrlcampaignmgr.dll (regsvr32 dvbcampaignmgrps.dll and regsvr32 dvbctrlcampaignmgr.dll).

    Note:

    When registering the DLL(s) on a 64-bit operating system, you must use the 64-bit version of regsvr32.exe. This can be found at C:\Windows\SysWOW64\regsvr32.exe.

  • Create the DeltaVAdmin account on a the non-DeltaV node with the same password as the DeltaVAdmin account on the Campaign Manager Server node.

    It is recommended that any accounts that jointly exist on DeltaV systems and non-DeltaV systems (such as the DeltaVAdmin account) be set as non-interactive users. That is, the user account cannot be used to log onto Windows. This can be set using GPOs or local policies (in a workgroup).

  • Set the DCOM option to permit unauthenticated users.

  • Log in to the non-DeltaV node as a user that matches a DeltaV user (same user name and password as on a DeltaV node). This user must have the appropriate DeltaV keys for the Campaign Manager actions to be performed (start/stop campaign or batch and so on).
