Understanding recipe parameters

Recipe parameters are parameters set at the recipe level. That is, they are not specific to a step in the recipe. You can use recipe parameters to defer or refer the value of a step parameter. For example, the phase input parameter, which becomes a step parameter in an operation, can obtain its value from the operation's recipe parameter (that is, the phase input parameter's value is deferred to the operation's recipe parameter). Additionally, a phase report parameter which becomes a step parameter in an operation can pass its value (refer it) to the operation's recipe parameter.

This allows you to create formulas for the recipe, set the value during production (which allows you to override a step parameter value and create less specific and more generic recipes), defer the recipe parameter as a step parameter to the next higher recipe level, use parameter values from a lower recipe level in a higher level (useful in unit selection policies).

Changes to batch input parameter values made in Control Studio online mode are never uploaded to the Batch Executive. Therefore, these values will be overwritten the next time the phase requests a download of parameter values from the Batch Executive (for example, by phase request code 1000 or 12xx).

Changes to batch input parameters (deferred or otherwise) might not be immediately reflected in the online values of their corresponding phase parameters. These values are downloaded to the phase only after the download requests previously mentioned occur.

Changes to batch report parameter values are only updated in the batch clients after the phase requests an upload to the Batch Executive (that is, when the phase request code 2000/22xx is issued).

Note:

Only step parameters of the category Input can be deferred to a recipe parameter. Only step parameters of the category Report can be referred to a recipe parameter.
