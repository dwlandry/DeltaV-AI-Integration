Updating Remote Zone Areas

If you re-run the auto-sense remote zone areas feature, its response depends on changes made to your Local Shared Areas and Remote Zone Areas configuration. This section outlines the possible changes, their effect on the auto-sense remote zone areas feature, and what actions are required for each type of change.

The following table summarizes the actions that may occur in response to an auto-sense request and lists possible reasons for the actions.

Action

Reason

No action.

All shared local areas in the remote zone are already in this zone's Remote Shared Areas folder.

Remote Zone Area created.

A shared local area in the remote zone has not previously been sensed.

Remote Zone Area created with a different name.

A shared local area in the remote zone has not previously been sensed, but its name conflicts with existing local area or remote shared area.

Remote Zone Area name updated.

Name of the remote shared area has been changed to match new name of shared local area in remote zone.

Popup appears: Remote Zone Area area_name no longer exists as a Local Shared Area. Delete existing area_name and re-scan.

An area has been deleted from the Shared Local Areas folder in the remote zone.

Popup appears: Conflict with existing Remote Zone Area area_name. Delete existing area_name and Auto-Sense Remote Zone Areas again.

Auto-sense cannot identify the shared local area in the remote zone that area_name is mapped to.
