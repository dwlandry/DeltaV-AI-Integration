VCAT for SIS module authorization approval

Version control for SIS module authorization is very similar to version control for recipe authorization. The major difference is that SIS modules have a Safety Integrity Level (SIL) associated with them. The SIL is determined from the calculated Risk Reduction Factor (RRF) assigned to the module on the SIS tab of the module's properties dialog. There are four SIL values (SIL0, SIL1, SIL2, and SIL3) but SIL0 does not require approval. In the Version Control Configuration dialog you must define between one and five signers for each of the three SIL values used.

When version control for SIS Module Authorization is enabled, all signers for the module's current SIL value must approve the module for the module to be authorized for download. The authorization state of the module is reported on the SIS tab of the SIS module properties dialog.

Changes to a module's configuration, Safety Integrity Level, or signers have the following effects:

  • If the SIL value of an approved SIS module changes, the module authorization state reverts to Not Authorized and the module must be approved by the signers assigned to the module's current SIL.

  • Adding a new signer to any SIL changes the authorization state of all previously authorized SIS modules at that SIL to Not Authorized.

  • Changing the configuration of a previously authorized SIS module (that causes a version change) changes the module's authorization state to Not Authorized.

  • Deleting a signer who was the only signer who had not approved a module causes the module's authorization state to become Authorized.

  • Modifying a signer does not affect the authorization state of any SIS module.
