Phase classes

The phase class defines the common configuration for a set of phases that can run on multiple units belonging to the same unit class. Typically, these are named for the action performed on a unit (for example, FILL, HEAT, DUMP, CLEAN, and so on).

Example of a DeltaV Phase Class

Phase class properties include:

  • Phase input parameters, which appear as the type Input in the corresponding phase class. The data types are floating point, integer, string, and named set.

  • Phase output parameters, which appear as type Report in the corresponding phase class. Data types are floating point, integer, string, and named set.

  • Phase messages

  • Number of phase partners

  • Algorithm parameters. Algorithm parameters define name and type.

  • One phase algorithm definition

  • Explicit associations with unit classes

Phase class definitions are located in the DeltaV system library under the Advanced Definitions category. Naming restrictions are system wide and are shared with other tagged objects. Therefore, the phase class name must be unique in the system.

The instance of the phase class will, by default, generate a system-wide unique name for the unit phase. However, this unit phase can be given a common shortened name that the operator will see and use.

In order for phase class configuration to affect unit modules, the phase class must be associated with the unit class from which the unit module is based. When the unit module is instantiated, a unit phase is created, and any input, output, and algorithm parameters configured at the phase class are also created. The phase algorithm definition (configured at the phase class) is used as the logic for the unit phase.

A phase class can be associated with one or more unit classes and, at the same time, have one or more phase algorithms and phase logic modules.
