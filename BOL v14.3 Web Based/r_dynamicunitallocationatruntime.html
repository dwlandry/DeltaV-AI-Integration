Dynamic unit allocation at run time

It is recommended to assign aliases in the order that they are sorted (which is based on the equipment train downstream alias hierarchy). This will provide maximum benefit from the downstream filtering capabilities. The operator does not have to assign all unit aliases at batch creation, and out-of-order assignments are accepted, but this practice can lead to the upstream assignments not converging with the units selected downstream.

In the case of flexible configurations where a unit can have multiple downstream units, the list is sorted alphabetically first and then by the upstream/downstream hierarchy.  When the operator selects a unit, the unit lists for all unit aliases are updated.

In circular configurations (where the recipe has a step that is before and after another step thereby using the same unit alias and hence unit, before and after another unit), the filtering is based on the following (in this order):

  1. Select units that are not downstream of anything. These are first and sorted alphabetically.

  2. For units that are downstream of another unit, sort them alphabetically.

  3. Where the circular configuration stops, list alphabetically by equipment train hierarchy.

In the Select Recipe and Select Equipment dialogs, a unit alias name displays in red text when there is a problem with assigning the unit alias. A reason for the red unit alias is displayed in a ToolTip (move the cursor over the unit alias name); however, while only one reason can be displayed, there could be multiple reasons why the unit alias is no longer appropriate.  Some reasons include: the equipment configuration doesn't support the unit alias (an upstream unit alias has no downstream unit aliases, making it impossible to have the downstream unit alias that is now displayed in red); or, the selected unit could no longer be appropriate for this unit alias based on other selections.  The red alias name is to alert the operator that the unit alias needs attention.

When the unit selection is set to Defer, the operator is presented with the list of unit aliases and possible units for each alias. This list is available at batch creation and equipment rebinding, and, when the step runs, in the Select Equipment dialog. 

When the selection mode is Defer and only one unit is configured, the Rebind and Batch Creation dialogs populate the unit field with the unit name. This behavior is consistent with recipes using fixed units.  If the downstream unit is set to use all units but only one unit exists in the unit class, then the Rebind and Batch Creation dialogs present a list to the operator where the operator selects the unit.

When a unit selection policy is used (selection mode is From_Policy), the operator monitors the batch progression without making a unit selection. However, when the system determines that no units match the criteria (that is, the list of appropriate units would be empty), the system prompts the operator to choose from a list of all units as configured in the equipment train for that unit alias and filtered based on the configured downstream units for the unit module immediately upstream.  A reason for the prompt is displayed; however, only one reason is displayed, there could be multiple reasons why the list did not resolve. 

In the rebinding or Select Equipment dialogs (but not in the Batch Creation dialog), the operator can override the upstream and downstream filtering by unchecking the Use upstream/downstream filtering option. 

If the $AVAILABLE parameter's value changes to an unavailable value (anything other than OK) after the batch starts, any phases that are running are not affected, but subsequent phases will fail to load on the unit (and subsequent unit selection policies could filter the unit out).
