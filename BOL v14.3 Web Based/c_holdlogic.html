Hold logic

The hold logic is the logic that is used to get the process into a safe state when a failure is detected. The phase transitions from the RUNNING or RESTARTING state to the HOLDING state and starts executing the hold logic when a HOLD is received, or if the FAIL_INDEX parameter is set. The phase checks to see if a request was being performed by the run logic and, if so, stores the request and sends an ABORT_REQUEST code to the Batch Executive. If the state was RUNNING, the run logic is suspended until the phase goes back into the RUNNING state. If the state was RESTARTING, then the restart logic is stopped. When the hold logic completes, the state changes to HELD and remains HELD until some user action is taken.

CAUTION:

It is not recommended to send requests in the Hold logic. However, if a request must be used, always check to see if the Watchdog parameter has tripped first. Write the logic to not sent the request if the Watchdog is tripped. Failing to do this can cause the phase to be unable to resume.
