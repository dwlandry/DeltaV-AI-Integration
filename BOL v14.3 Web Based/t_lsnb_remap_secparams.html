Remapping secure parameters

As a configuration evolves some secure parameters may no longer be referenced so the database automatically removes them from their assigned LSNB publisher slots without changing or affecting the mapping of the remaining secure parameters. Logic solvers that are unaffected by the removing of secure parameter references therefore do not require downloading. Any secure parameters added to the database later are placed in the empty slots.

It is also possible to manually remap secure parameters by selecting the Enable remapping check box.

CAUTION:

Manual remapping of secure parameters may be required in rare circumstances and should be performed only by experienced personnel. Manual remapping affects all modules referencing the remapped secure parameters.

It is possible to manually move secure parameters to free slots. That is, you can reassign a currently mapped reference to an open publisher slot in the same LSNB. For example:
  • LSNB1 exists on an LSN which has CSLSs with several secure parameters referenced by other LSNBs on the Global Safety Network, so that LSNB1 has at least two publishers.
  • One of these publishers has had secure parameters deleted from it so that it has at least one free slot.
  • Another publisher has a secure parameter of the same type (Boolean or non-Boolean) as the free slot, so that it can be remapped there.
  • The Secure Parameters dialog for LSNB1 is open.

To remap secure parameters manually:

  1. Select the Enable remapping check box The Show references to parameters check box is automatically selected and then grayed out. The Secure Parameters dialog refreshes. References appear and remain visible as long as remapping is enabled.
  2. Select a secure parameter to be remapped from the list. This makes the Remap button selectable.
  3. Click the Remap button. The Remap Secure Parameter dialog opens.

    The Remap to… area lists all publishers in the LSNB that the selected secure parameter can be remapped to. The first of these publishers is selected. If there are no publishers that the secure parameter can be remapped to, the display of the Remap Secure Parameter dialog closes and an error message appears.

  4. Select a different publisher to remap the secure parameter to or select Cancel to close the dialog.
  5. Click the OK button. A confirmation dialog appears that lists the SIS modules and CSLSs that contain global references to the secure parameter and explains that the remap changes their CRCs so that they will need to be revalidated and re-downloaded.
  6. Click Yes to confirm the remap of the selected secure parameter. The Remap Secure Parameter dialog disappears and the Secure Parameters Dialog reappears.
  7. Remap additional secure parameters as needed.
  8. Uncheck the Enable remapping checkbox in the Secure Parameters dialog. The Show references to parameters checkbox becomes selectable.
  9. Uncheck the Show references to parameters check box. The Secure Parameters dialog no longer displays references.
