Manual phase control security

When developing your DeltaV Batch control strategy, it is important to understand how manual phase control is affected by security. The DeltaV system differentiates between DeltaV phase control and manual phase control. When a batch is run under DeltaV control, the DeltaV security checks the user privileges for the appropriate keys. For example, when the operator starts a batch, DeltaV security checks that user to see if the user has the key to the BATCH_OPERATE lock, which contains the BATCH_START function. The same security check occurs when the operator stops or holds a batch, or acknowledges prompts. If the operator does not have the appropriate key (BATCH_OPERATE in this case for the functions BATCH_STOP, BATCH_HOLD, or BATCH_ACK_PROMPT, respectively), the operator is not allowed to complete the request.

Note:

All Batch functions are assigned to the BATCH_OPERATE lock by default. You can reassign the functions to user-defined locks as needed by your security scheme. Refer to the topic and the DeltaV User Manager help for more information.

When a batch is run under manual phase control, DeltaV security checks to see if the user (operator) has the key to the BATCH_OPERATE lock, which contains the BATCH_PHASE_CONTROL function by default.

Note:

If you have assigned this function to another lock, then the user will have to have the key to the user-defined lock. 

DeltaV security treats manual phase control as a special situation; such as, a maintenance issue, debugging a new batch, recovering a batch, and so on.  Therefore, DeltaV security allows the operator to perform any of the batch actions (except Acquire and Release) without checking for any other key, other than the one containing the BATCH_PHASE_CONTROL function. For example, when the operator takes manual control, that operator can start the batch (provided it was acquired already), hold the batch, abort the batch, restart the batch, and so on. DeltaV security only checks for the key to the lock containing the  BATCH_PHASE_CONTROL function. Therefore, even when you reassign the BATCH_PHASE_CONTROL function to another lock, the batch commands are still available to the user (except the Acquire and Release commands). Refer to our example, below, for clarification.

There is one exception to this rule, Verification. On any action that has verify turned on, DeltaV security checks that the verifier has the key to the BATCH_ACTION_VERIFY function lock.

Note:

Prompts originating from a manual phase are subject to checking on BATCH_ACK_PROMPT function.
