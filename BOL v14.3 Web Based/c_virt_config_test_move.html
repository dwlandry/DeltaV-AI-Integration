Configure virtual system, test, and move configuration to production system

After you have defined and populated the virtual system with the required hardware, configure the system, check the logic, and when satisfied with the configuration, move it to the production system.

Configure the virtual safety system

Configure modules, CHARMs, and DST assignments. You must completely configure these items in the virtual system so that no additional configuration is required after you import the virtual system into the production system. This ensures that module CRCs do not change from the virtual system to the production system.

Examine and test the configuration

Perform all tests and logic checkout your situation requires. You cannot simulate I/O at the CHARM level but you can use the SIMULATE_IN parameter on function blocks and Debug mode in DeltaV Explorer. You can examine the virtual hardware in DeltaV Diagnostics. The virtual hardware appears nearly identical to physical hardware with a few exceptions. For example, the revision numbers of the virtual hardware and software do not match those of physical hardware.

Note:

If a yellow triangle download indicator appears on a running virtual CSLS or LSNB and an attempt to download the node results in the following messages in the download dialog: 

SISCTLR:CSLS_NAME
SISCTLR:1:ERROR: An error occurred (error code 
2097172,LS_SLS_IN_REDUCED_OPERATION).
You can recover and download the LSNB or CSLS by following these steps:
  1. Open DeltaV Diagnostics.
  2. Select the CSLS or LSNB.
  3. From the context menu select Force Reset On Active.

    A secure write confirmation dialog box appears.

  4. Confirm the secure write.
  5. Ignore or dismiss any messages that appear related to the secure write request.
  6. Download the CSLS or LSNB from DeltaV Explorer.

    The download should complete without errors.

Move virtual configuration to production system

After you have completed your logic check, follow the instructions to export the configuration from the virtual system and import it into the production system.
