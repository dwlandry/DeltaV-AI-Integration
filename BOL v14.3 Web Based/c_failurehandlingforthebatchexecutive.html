Failure handling for the Batch Executive

If the DeltaV Batch Executive fails (that is, stops running during the execution of a batch), the phase logic in the controller continues to execute. The Watchdog timer times out, allowing the operator to take control of the phase through the phase faceplate at the operator's workstation. No new phases will be started since the Batch Executive is no longer communicating.

Warning:

Caution is advised when downloading phase logic modules (PLM) when the PLM is currently active. The download leaves the PLM in the IDLE state and, when restarted, the recipe will run that phase again.

When the problem with the Batch Executive is corrected, it is possible to do a Warm Restart to restore the Executive to the last known state. However, this assumes that the batch log files are available for the Batch Executive to use in the restart (that is, the files were not corrupted and the hard drive is functioning). If a Warm Restart is possible, the batch list is populated with all recipes that were known about at the time the failure occurred. In addition, all recipes are placed in Manual mode. After assessing the status of each recipe (for example, the operator might want to make active step changes, abort the recipe, and so on), the operator can restart the recipe as appropriate.

If the batch does not complete the warm restart successfully, perform a cold restart and active step change to the point where the batch stopped.

If several batches had been waiting to acquire the same unit before the shutdown, they would have been queued in a certain order, dependent on when they made the acquire request. After the warm restart, these batches are queued in exactly the same order they were in before the warm restart. Review the order of the queue on the Arbitration screen of the Batch Operator Interface and verify that the current order is the correct order for the batches to use that unit.
