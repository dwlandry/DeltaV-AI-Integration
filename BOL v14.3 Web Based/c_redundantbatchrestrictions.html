Restrictions for Redundant Batch systems

Once a redundant subsystem is configured, you cannot concurrently enable any other subsystem (redundant or not) on the Application Station. The Batch Executive and Campaign Manager are considered individual options of the one Batch subsystem for the purpose of Redundant Batch.

In a Redundant Batch system, only the Batch Executive subsystem and Campaign Manager subsystem are redundant. DeltaV applications are not supported for redundant operation. That is, the applications themselves are not redundant, even though they appear in Start > DeltaV of either partner in the Application Station pair with Redundant Batch enabled. While you can start these applications, inconsistent and/or erroneous data can result after a switchover.  Therefore, it is strongly recommended that you not run the DeltaV applications on the Application Station pair being used for Redundant Batch.

Note:

You can run the Batch Application Manager on the active node (either active Batch Executive or active Campaign Manager) to access advanced configuration options for that server. Other functions (start, stop, verify phases) are available when running the Batch Application Manager from other workstations (for example, the ProfessionalPLUS).

Additionally, it is strongly recommended that you not install other applications on the Application Stations where you have enabled the Redundant Batch feature, as these applications do not run redundantly and their operation is not reliable following a switchover and might affect the stability of an Application Station where Redundant Batch is running. This includes DeltaV Soft Phase executables.

Both workstations in a Redundant Batch pair must be running the same operating system (server or workstation) and must be the same service pack for that operating system. The operating system must comply with the DeltaV system requirements.
